## 1. 系统定位

股票投研系统，核心三块能力：

1. **数据采集**：多数据源抓取 A 股 / 美股行情、基本面、公告、新闻，保证及时、准确、可回溯
2. **数据展示**：清洗、聚合、可视化，面向用户提供清晰看盘 / 分析界面
3. **荐股（选股策略）**：基于数据与策略模型产出股票推荐 / 催化剂信号，可解释、可追踪、可评估——**核心资产**，重构中重点保护与强化

## 6. 重构硬性原则（brief §"重构硬性原则"逐字落定，全项目**不得妥协**）

1. **长期正确优先**：设计以长期可维护、可演进为准；**禁止临时补丁、投机取巧、埋技术债**
2. **删干净、零冗余**：重构后不再使用的东西**必须彻底删除**——废弃代码、死分支、无用依赖、闲置配置、遗留接口、失效采集器，以及**数据库中不再使用的表、字段、索引、迁移脚本、存量脏数据**。禁止"留着以防万一"
3. **不误删有价值资产**：与"删干净"对立平衡——**荐股策略、有效历史数据、经过验证的核心逻辑**必须重点保护；删除前反复确认；**宁可多问一句，不可误伤核心资产**
4. **不考虑向后兼容**：无需保留旧接口 / 旧数据结构 / 旧调用方；不做兼容层或过渡方案
5. **可扩展性**：模块边界清晰、低耦合高内聚。数据源、指标、选股策略作为**插件低成本新增**，不改动核心链路
6. **设计合理**：分层、命名、数据模型、依赖方向经得起推敲；避免过度设计也避免设计缺失。**采集层 / 存储层 / 计算层 / 策略层 / 展示层职责清晰**
7. **测试充分**：核心逻辑单元测试；数据采集与策略计算关键链路集成测试；荐股策略**可复现回测 / 验证**；**禁止"没测过就说完成"**

---

## 7. 领域特定要求

- **数据质量**：缺失值、除权除息、停牌、时区 / 交易日历、数据源冲突与去重，保证可回溯
- **策略可解释**：荐股结果说明"为什么推荐"（触发了哪些信号 / 因子）；**非黑盒输出**
- **性能**：大批量历史数据的采集与计算考虑吞吐与增量更新；**避免全量重算**
- **数据安全**：密钥 / 凭证**不得硬编码**，统一走配置 / 环境变量 / 密钥管理；**严禁提交到版本库**
- **合规与风险提示**：荐股属投资建议范畴，输出**带风险提示**；**不做绝对收益承诺**

## 9. 质量门禁（每次提交 / 合并前必须通过）

- 代码通过格式化与静态检查（`tsc --noEmit`、eslint、`gofmt / go vet` 若涉及、pyflakes / ruff 若涉及）
- 相关单元 / 集成测试全部通过；**禁带失败测试提交**
- 无新增硬编码密钥；必要时对历史提交做密钥扫描并清理
- **US-038 强制**：`Math.random()` 静态 lint 拒合入；策略/回测/因子路径必须用 `SeededRandom`（Park-Miller LCG）

## 13. Phase 0 蓝图（brief §"Phase 0"，落地时机 = 方案签字后）

- **先建安全网**：代码干净基线 commit / 分支；DB 可恢复备份 / 快照
- **判定有据**：每项删除有依据（静态分析 / 引用检索 / 覆盖率 / 调用链），记入清理清单；**凭感觉删禁止**
- **保护优先**：删除前先明确重点保护清单（`contracts/protect.md`）
- **分类清理**：
  - 代码层：死代码 / 无引用文件 / 注释旧逻辑 / 废弃接口 / 失效采集器 / 无用依赖 / 闲置配置
  - 数据层：无用表 / 字段 / 索引 / 过期迁移 / 脏数据
- **顺带密钥扫描**：清理时扫代码与历史提交中的密钥
- **小步删 + 可编译**：分批删除，每批保证能编译、已有测试通过，单独 commit
- **全程留痕 + 阶段验收**：清理清单与变更日志；完成后小结（删了哪些、体量变化、剩余待确认）
