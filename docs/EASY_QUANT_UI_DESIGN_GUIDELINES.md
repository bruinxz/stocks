# QuantX 简易版 UI 设计规范

本文档整理自 `/Users/bruinxz/UI_DESIGN_GUIDELINES.md`，并结合当前
`/workspace/easy` 的实际实现沉淀为项目内约束。后续涉及简易版、易上手流程、
新手引导、模板选择、查数据、跑回测、模拟观察等前端迭代时，必须优先遵守本规范。

当前参考实现：

- 页面：`frontend/src/pages/workspace/EasyQuantWorkspace.tsx`
- 样式：`frontend/src/pages/workspace/EasyQuantWorkspace.css`
- 契约测试：`backend/tests/services/easy-quant-workspace-ui.test.ts`

## 1. 一句话定调

简易版采用“暖纸风”：米色纸张底、黑墨文字、陶土橙强调、克制描边、少量手绘线稿。
交互采用“整屏分段”：一屏一个动作，滚动推进用户完成第一套量化策略。

简易版面向新手，设计目标不是展示所有能力，而是降低第一次使用的心理负担：

- 先给用户一个清晰入口。
- 一次只推进一个决策。
- 把复杂信息收进抽屉、详情页或专业版。
- 用金融语义色让收益、回撤、风险一眼可辨。

## 2. 适用范围

必须遵守本规范的范围：

- `/workspace/easy` 和后续简易版子页面。
- 面向新手的 onboarding、模板选择、流程引导、空状态、结果说明。
- 从专业版能力抽取出来的“简化入口”。

可以不完全遵守的范围：

- `/workspace/lab` 专业版可继续保持更高信息密度和现有后台工具风格。
- 历史页面、运维页、纯表格型后台页可以逐步迁移，不要求一次性重做。

## 3. 设计令牌

简易版优先使用 `--eq-*` 令牌。不要在组件里散落新的裸色值、裸圆角和临时阴影。

### 3.1 色彩

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--eq-paper` | `#f7f2e8` | 页面纸张底色 |
| `--eq-sheet` | `#fbf8f1` | 卡片、面板底色 |
| `--eq-ink` | `#171512` | 主文字、标题、深色主按钮 |
| `--eq-muted` | `#48433c` | 次要文字、说明文字 |
| `--eq-clay` | `#c96338` | 陶土橙强调色，当前态、选中态、手绘线稿 |
| `--eq-green` | `#2f7d4b` | 收益、正向、低风险 |
| `--eq-amber` | `#9a6a12` | 中风险、轻警示 |
| `--eq-red` | `#b64232` | 回撤、亏损、高风险 |
| `--eq-line` | `rgba(23, 21, 18, 0.16)` | 常规描边 |
| `--eq-soft-line` | `rgba(23, 21, 18, 0.09)` | 浅分隔线 |

### 3.2 字体

| 变量 | 建议值 | 用途 |
| --- | --- | --- |
| `--eq-display-font` | `'Heiti SC', 'STHeiti', 'PingFang SC', 'Noto Sans SC', 'Microsoft YaHei', Arial, sans-serif` | 标题、大数字、主叙事 |
| body font | `'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', Arial, sans-serif` | 正文和按钮 |
| mono font | `'JetBrains Mono', 'SFMono-Regular', Consolas, monospace` | 百分比、时间戳、日志、代码感数据 |

不要在简易版使用宋体、仿宋、楷体作为默认界面字体。

### 3.3 圆角、描边、间距

- 卡片圆角默认 `16px`，按钮和小卡片可用 `9px` 到 `14px`。
- 卡片以浅描边为主，少用强阴影。
- 间距优先使用 `8px` 倍数：`8 / 12 / 16 / 20 / 24 / 32 / 40 / 56`。
- 不要堆叠卡片套卡片。大区块是整屏 section，小卡片只承载具体选择或指标。

## 4. 色彩语义

金融语义色不能混用：

- 收益、正向、低风险：绿色 `--eq-green`。
- 中风险、轻警示：琥珀 `--eq-amber`。
- 回撤、亏损、高风险：红色 `--eq-red`。
- 选中态、当前步骤、手绘线稿：陶土橙 `--eq-clay`。
- 普通链接、刷新、次要说明：中性色 `--eq-muted` 或 `--eq-ink`。

避免使用蓝色旧后台风格令牌，例如 `--primary`、`--backtest-*`、`--dashboard-*`。
简易版不走蓝色 SaaS 后台风。

## 5. 布局原则

### 5.1 一屏一个任务

简易版主流程按以下节奏组织：

1. Hero：开始第一套量化策略。
2. 动线：说明四步流程。
3. 选模板：选择策略模板。
4. 查数据：确认数据齐备。
5. 跑回测：看收益、回撤、胜率。
6. 模拟观察：观察策略运行。

每屏只服务一个任务，不要在同一屏塞多个主流程节点。

### 5.2 整屏分段

桌面端使用单一滚动容器，例如 `.eq-scroll-root`：

- 容器负责 `overflow-y: auto`。
- `scroll-snap-type` 放在滚动容器上，不要放在 `html` 或 `body` 上。
- 每个 section 使用 `min-height: 100%` 和 `scroll-snap-align: center`。
- 各屏内容垂直居中，但卡片内部信息要收紧，避免标题、图标、正文上下散开。

移动端退化为自然单列长滚动：

- 关闭 scroll snap。
- `min-height` 改为 `auto`。
- 隐藏右侧分屏圆点导航。

矮窗口必须适配：

- 在 `max-height: 760px` 一类断点压缩 padding、字号和卡片高度。
- 内容放不下时关闭 scroll snap，退回普通文档流。
- 不允许两个模块互相挤进同一屏。

### 5.3 分屏导航

右侧圆点导航保持轻量：

- 默认只显示圆点。
- hover 时显示标签。
- 很宽的桌面屏才可以常显当前标签。
- 圆点不能覆盖或挤压主卡片内容。

程序化跳屏要可靠。当前实现采用确定性跳转：

- 点击时临时关闭 snap。
- 暂停 scroll-spy 抢状态。
- 用 `behavior: 'auto'` 跳到目标 section。
- 下一帧再校准一次位置。
- 短延迟后恢复 snap。

不要直接使用 `section.scrollIntoView({ behavior: 'smooth' })` 作为核心跳屏方案。
它在某些环境会被 snap 或滚动状态回写打断，表现为高亮点变化但页面弹回顶部。

## 6. 信息架构

### 6.1 减少重复

同一信息不要在多个区域重复出现。尤其避免：

- 左侧进度、主区标题、右侧卡片同时重复“当前步骤”。
- 同一个功能出现两种叫法，例如“查数据 / 检查数据 / 数据体检”。
- 页面内多个深色主按钮抢注意力。

### 6.2 单一主 CTA

每屏最多一个深色主 CTA。按钮文案要包含动作：

- 推荐：“下一步：查数据”“开始回测”“进入模拟观察”。
- 谨慎使用：“开始”“提交”“继续”。

Hero 可用“开始”，但进入流程后的主按钮必须写明下一步。

### 6.3 详情收进抽屉

简易版主屏只保留新手需要的判断信息：

- 当前该做什么。
- 能不能继续。
- 为什么推荐。
- 下一步按钮。

复杂指标、数据字段、模板对比、日志细节收进抽屉或专业版。

## 7. 视觉元素

### 7.1 手绘线稿

手绘线稿是当前风格的识别点：

- 使用单色线稿，颜色优先 `--eq-clay`。
- 图标必须与功能语义匹配，例如放大镜表示查数据，走势图表示回测，望远镜表示观察。
- 不要为了装饰放无关图形。

### 7.2 卡片

卡片样式保持克制：

- 浅纸底、浅描边、低阴影或无阴影。
- 卡片内部信息成组聚合，避免顶部一行、中间一个图、底部一段文字分得过开。
- 选中卡片需要明确：描边增强 + 角标或勾选状态。

### 7.3 指标

指标使用语义色：

- `+18.7%` 这类收益为绿色。
- `-8.4%` 这类回撤为红色。
- 中性指标为黑墨色。

数字可使用 mono 字体，但不要让数字变成花哨装饰。

## 8. 动效

简易版动效只服务“分屏叙事”：

- section 首次进入视口时做轻微淡入和上移。
- 触发一次即可。
- 尊重 `prefers-reduced-motion`。
- 不使用滚动劫持、强制翻页、复杂视差。

## 9. 组件沉淀方向

当前简易版仍主要集中在单页文件中。后续继续迭代时，建议逐步抽出以下原语到
`frontend/src/components/eq/`：

- `EqScreenSection`：整屏 section、入场动画、移动端退化。
- `EqDotNav`：分屏圆点导航、可靠跳屏、scroll-spy。
- `EqPanel` / `EqCard`：暖纸面板、描边、圆角。
- `EqRiskTag`：`low | medium | high` 到绿、琥珀、红。
- `EqMetricValue`：`positive | negative | neutral` 到收益绿、回撤红、中性黑。
- `EqPrimaryButton` / `EqGhostButton`：单一主 CTA 和次级动作。
- `EqSketchIcon`：可复用的功能线稿图标。

抽组件时不要为了抽象而抽象。优先从重复样式和重复交互中抽。

## 10. 提交前自查

改动简易版 UI 前，至少检查以下项目：

- 是否仍然是一屏一个任务。
- 是否只有一个深色主 CTA。
- 文案是否使用统一术语，尤其“查数据”。
- 金融语义色是否正确：收益绿、回撤红、风险绿/琥珀/红。
- 是否没有蓝色旧后台风格和无关装饰。
- 右侧圆点是否能跳到正确屏，高亮是否同步。
- 矮窗口下是否不会模块串屏。
- 移动端是否自然单列滚动。
- 文字对比度是否足够。
- 手绘图标是否和功能相关。

## 11. 自动化守护

当前已有契约测试：

```bash
node backend/tests/services/easy-quant-workspace-ui.test.ts
```

新增或调整简易版 UI 时，优先补充这个测试，检查：

- 暖纸风令牌是否仍在。
- 是否避免蓝色旧风格。
- 分屏导航是否仍使用专用滚动容器。
- 风险标签和回测指标是否有语义色。
- 移动端和矮屏是否退化为普通流。

前端构建验证：

```bash
cd frontend && npm run build
```

构建中的历史 lint warning 不等于本次改动失败，但新增 TypeScript 编译错误必须修掉。
