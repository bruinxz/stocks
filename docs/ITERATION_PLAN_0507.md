# 0507 项目迭代计划：数据源韧性 + AI 研究闭环 + 产品体验升级

## 当前判断

本项目已经具备「行情数据同步 → 策略/组合模拟 → TradingAgents AI 研报 → 前端可视化」的主链路，但继续优化的核心瓶颈在三处：

1. **数据源韧性不足**：原先历史 K 线主要依赖 AKShare，东方财富历史 K 线未实现，新浪未进入统一 fallback，失败后缺少可观测健康状态。
2. **AI 研究与量化回测尚未闭环**：TradingAgents 可以输出多智能体研报，但还没有沉淀成可筛选、可比较、可回测的结构化信号库。
3. **产品体验需要持续降 AI 感**：首轮页面已重构，但仍需要用真实数据密度、状态反馈、交互细节和信息架构继续提升专业感。

## 已启动的第 1 阶段：数据源底座升级

目标：让系统从「某个接口失败就僵住」升级为「多源 fallback + 健康评分 + 可观测」。

- 新增数据源健康表 `data_source_health`，记录 provider、优先级、能力、成功/失败次数、连续失败、最近错误、健康分。
- 新增统一 provider 定义，覆盖 Tushare、Baostock、AKShare、东方财富、新浪财经、TradingAgents。
- 实现东方财富历史 K 线接口，修复此前 `queryHistoryKData not implemented` 的硬伤。
- 历史 K 线 fallback 链升级为：Tushare（可选）→ Baostock（可选）→ AKShare → 东方财富 → 新浪。
- Tushare / Baostock 以可选源接入：未配置 token 或未启用时显示 disabled，不阻断服务。
- 系统监控页新增「数据源韧性」卡片，展示综合状态、启用源、健康分、能力、最近错误。

## 第 2 阶段：数据质量与补数策略

目标：把「有数据」升级为「可信数据」。

1. 建立日线质量扫描任务：
   - OHLC 逻辑校验：最高价/最低价/开收盘关系。
   - 异常涨跌幅识别：超过 40% 标记为复权或源异常。
   - 重复交易日检查。
   - 周末容忍后的缺口检测。
2. 为每只股票沉淀数据质量画像：
   - 覆盖率、最近更新日、异常条数、缺失区间。
   - 可在市场页/组合模拟页提示「数据可信度」。
3. 补数策略分层：
   - 近 30 日高优先级补数。
   - 用户自选股、组合模拟常用股票优先补数。
   - 低质量股票进入后台低频修复队列。

## 第 3 阶段：TradingAgents 结构化落地

目标：从「AI 文本报告」升级为「可检索、可回测、可复盘的投研信号」。

1. 为 TradingAgents 增加健康探测与任务观测：
   - 后端周期探测 `/openapi.json` 或健康端点。
   - 在系统监控页和 AI 页面显示 TradingAgents 在线状态。
2. 建立 AI 信号归档表：
   - 股票、日期、最终决策、置信度、风险等级、关键理由、引用数据源。
   - 研报 detail 继续保留，但前端优先展示结构化摘要。
3. 建立「AI 建议 vs 实际收益」验证面板：
   - 买入/观望/卖出后的 1/3/5/10/20 日收益表现。
   - 按行业、市值、市场环境分组统计命中率。
4. 将 AI 信号接入组合模拟：
   - 可选择「仅买入 AI 看多股票」。
   - 可选择持有 N 日后卖出，形成事件驱动策略。

## 第 4 阶段：策略与组合模拟增强

目标：把组合收益模块从单次模拟升级为策略实验台。

- 支持股票池：自选股、AI 每日优选、行业、指数成分、手工导入。
- 支持买入规则：等权、按 AI 置信度、按波动率反向、按市值过滤。
- 支持卖出规则：固定持有天数、止盈止损、AI 降级、均线跌破。
- 支持结果对比：多持有周期收益矩阵、最大回撤、胜率、收益分布。

## 第 5 阶段：产品体验持续优化

目标：从「功能页面」升级为「专业工作台」。

- 页面信息层级继续精简：首屏只展示关键指标，复杂信息折叠到明细。
- 增强空状态与异常状态：明确告诉用户下一步该做什么。
- 统一图表语言：收益、回撤、健康分、任务进度使用一致色彩语义。
- 增加任务反馈：同步任务预计耗时、当前数据源、fallback 轨迹。
- 增加可解释性：每个结果面板附「数据范围 / 数据源 / 计算口径」。

## 验收标准

1. 后端与前端构建必须通过。
2. `/api/market/data-sources/health` 可用，并能看到每个数据源健康状态。
3. 历史 K 线在 AKShare 失败时能自动 fallback 到东方财富或新浪。
4. 数据更新页能展示数据源健康状态，不影响原有队列、日志、统计功能。
5. 后续每轮迭代都需要至少覆盖：构建验证 + 关键接口烟测 + 页面可用性检查。
