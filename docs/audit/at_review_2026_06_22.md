## 真发现的 P0/P1 — 5 个 (全部已修)

### P0 #1 — FE↔BE Contract 字段名漂移 8 处 (阻塞核心功能)

**严重程度**: P0 阻塞. 用户在"持仓与复盘 → 模拟盘管理"看到的 UI **完全是空的**:
- 表格"持仓数" / "7d 收益" / "策略 chip" / "因子 chip" 永远空白
- 新建/编辑 Modal Transfer 控件**完全无法选策略/因子** (前端读 `s.key/.brief`, 后端返 `strategy_key/description`)
- Drawer 详情交易表"价格" / "盈亏" 列空
- Drawer 净值曲线永远 Empty (BE 不返 `recent_snapshots`)

**真验证**: 8 字段全 curl prod 实际对比:
```
FE 期望:                  BE 实际返:
position_count            positions_count
recent_7d_return_pct      return_7d_pct
strategy_display[].key    strategy_display: ["策略名"]
factor_display[].key      factor_display: ["因子描述"]
recent_snapshots[]        (NOT PRESENT)
execute_price (trade)     price: null
realized_pnl (trade)      (NOT PRESENT)
strategy.key / factor.key strategy_key / (none)
```

**修法**: 改后端契约对齐 FE (FE 形态更合理 — chip 必须含 `key` 才能让 Transfer 锚定).
- `PortfolioListItem`: `positions_count` → `position_count`; `return_{7,30}d_pct` → `recent_{7,30}d_return_pct`
- `StrategyDisplayChip = {key, name, brief}`; `FactorDisplayChip = {key, name, category}` (从 `string[]` 升级)
- `PortfolioDetailTrade`: 新增 `execute_price` / `realized_pnl`; 去掉 `trade_date: "undefined"` 假字段
- `PortfolioDetail`: 新增 `recent_snapshots: {date, total_value}[]` (拉 7 日, reverse 给 Recharts 升序)
- `AvailableStrategy`: `strategy_key` → `key`; `description` → `brief`
- `AvailableFactor`: 新增 `key` (复用 factor.name)

**Commit**: `d284288`. **新加 test [15]**: 26 个 fs+regex meta-guard 防再次漂移.

### P1 #2 — Audit 日志写入失败 (4 个 mutation 操作审计丢失)

**真追日志发现**:
```
[PaperTradingPortfolioCrudService] audit log 写入失败 (user=4 action=create pid=54):
  value too long for type character varying(20)
```

**根因**: `risk_alerts.symbol` 列 schema VARCHAR(20), AT-1 写 `'SYSTEM:PORTFOLIO_CRUD'` 是 21 字节, INSERT 永远失败. `writeAuditLog` 的 try/catch 把错误吞了, 用户表面看 "已删除/已重置" 成功 message, 但 4 个 mutation (create/update/reset/delete) 的 LOW RiskAlert 审计行**全部丢失**.

**真验证 (prod)**:
- 修前: `SELECT * FROM risk_alerts WHERE rule_id='portfolio_crud'` → 0 rows
- 修后: 1 个 create 操作 → 1 row LOW/SYSTEM:PT_CRUD/portfolio_crud (具体到 `用户 4 创建 portfolio 55 | {...}`)

**修法**: `SYSTEM:PORTFOLIO_CRUD` (21字节) → `SYSTEM:PT_CRUD` (14字节, 留 6 字节余量). **Commit**: `58743e0`.

### P1 #3 — User 2 (lym) 8 个 active portfolio 静默被关 (silent regression)

**SQL 校对发现**:
```
user_id | enabled | total
   2    |    0    |   8     ← 全关了 ❌
   4    |    8    |   8     ← admin-keep SQL 救了
```

**根因**:
- AT-1 主 migration 默认 `auto_trade_enabled=false` 防被动失血
- `admin-keep` SQL **只补了 `user_id=4` (stock)**
- 但 `user_id=2` (lym) 也有 8 个 active portfolio 在 cron 35 `all_portfolios=true` 下被实际跟单 (最近 trade 2026-06-18)
- 部署后 lym 的 8 个盘**静默被关**, 用户视角是"prod 之前在跑现在突然不跑了, 没告警"

**修法**: 新 migration `2026-06-22-restore-active-portfolios-auto-trade.sql`, 用"最近 30 天有真实 trade"判定 — 比硬编码 user_id 更稳健.

**prod 真应用**: `BEGIN; UPDATE 8; COMMIT;` → 验证后 `user 2 enabled=8/8, user 4 enabled=8/8`. **Commit**: `8d49026`.

### P1 #4 — `portfolio.strategy_keys` 配置完全不生效 (核心承诺没兑现)

**代码审计发现**: `portfolio.strategy_keys` 是 AT-1 主交付的核心字段, 用户在 UI 上勾"我这盘只接 ma_trend / macd_trend 的信号". `autoBuyFromSignals` 接受 `options.strategy_keys` 透传做 `candidateSignals filter`. 但 `runAutoSync` 调 `autoBuyFromSignals` 时**根本没读 `portfolio.strategy_keys`**, 只透传 cron task parameters.

**真测试结果**: 创建 `REVIEW-TEST-AT` 盘绑定 `[ma_trend, macd_trend]` → cron 跑这盘时仍会给所有 29 策略的信号下单. **字段存了不用**, 是 AT-1 的核心承诺没兑现.

**修法**: `runAutoSync` 调 `autoBuyFromSignals` 时:
- 优先级 caller `options.strategy_keys` > `portfolio.strategy_keys` > 空 (= 接所有)
- IIFE 干净表达三级 fallback
- `enabled_factors` 不在这里 wire (那是策略层 factor weights, 未来在 `MultiFactorAlpha` 里单独接)

新增 test [14] 升级 meta-guard 验证方法体含 `portfolio.strategy_keys` + IIFE 模式. **Commit**: `1e19332`.

### P2 #5 — FE Modal 长度限制比 BE 严, 拒绝合法输入

**真验证**: FE name `max:32`, BE max 100. 用户输入 33-100 字合法盘名 → 前端拒了, 后端 OK. 描述同样: FE 200 字 vs BE 1000 字.

**修法**: 改 FE Modal Form rule `{max: 100, message: '盘名最多 100 字'}` + `description {max: 1000}`. 系统介绍 `SYSTEM_OPERATIONS_MD` 6.1 节同步修. 顺带修了 `GlobalPortfolioSelector` 行 64 也用 `p.positions_count` 永远 undefined → `0 持仓` 显示. **Commit**: `2f9c322`.
