## 1. 启动与登录

### 1.1 环境准备

| 工具 | 版本要求 | 用途 |
|------|----------|------|
| Node.js | ≥ v18 | 后端 + 前端运行时 |
| Docker & Docker Compose | 最新 | PostgreSQL（TimescaleDB） + Redis |
| Git | 任意 | 拉代码 |
| Python 3 | ≥ 3.9 | AKShare 数据源（已随后端安装） |

> 验收建议：先 `node -v`、`docker --version`、`git --version` 三连，再继续。

### 1.2 启动后端

```bash
# 1. 拉代码（首次）
git clone <your-repo-url>
cd stocks

# 2. 启动 PostgreSQL + Redis（首次会拉镜像）
docker-compose up -d

# 3. 启动后端
cd backend
npm install
cp .env.example .env       # 默认配置足够本地开发
npm run check-env          # US-068 校验 env 完整（缺关键字段会立即提示）
npm run dev                # 默认 3000 端口
```

后端启动成功后，访问 <http://localhost:3000/health> 应返回 `{"status":"ok"}`；访问 <http://localhost:3000/health/detail>（US-096）可看到所有依赖（DB / Redis / AKShare / TradingAgents）的实时状态。

## 2. 数据同步

> 新账户登录后 DB 是**空的**，必须先把基础数据拉下来才能跑因子和策略。本平台的数据源是 **AKShare**（开源 A 股全市场接口），无需付费 API key。

### 2.1 推荐顺序：先存量、再增量

#### 阶段 A：基础档案（一次性，~3 分钟）

```bash
cd backend

# 全 A 股列表 + 当前市值 / 行业 / 上市日期
npm run sync:stock-basic        # 约 5000 只股票
```

#### 阶段 B：行情主力（一次性 + 每日增量）

```bash
# 近 5 年日 K 线（约 7-10 分钟，看网速）
npm run sync:daily-bars -- --start=2021-01-01 --end=2026-06-08

# 财务数据（季度数据，几分钟）
npm run sync:financial-report -- --year=2024 --year=2025 --year=2026
```

#### 阶段 C：A 股特色数据（首次同步选近 1-3 个月即可）

| 命令 | 数据 | 频率建议 |
|------|------|---------|
| `npm run sync:northbound` | 北向资金每日持股 | 每日 18:00 |
| `npm run sync:dragon-tiger` | 龙虎榜（含游资 / 机构席位） | 每日 18:00 |
| `npm run sync:limit-up` | 涨停 / 跌停股池 | 每日 16:00 |
| `npm run sync:industry-flow` | 行业资金流入流出 | 每日 16:00 |
| `npm run sync:earnings-forecast` | 业绩预告（盈喜 / 盈警） | 财报披露季每日 |
| `npm run sync:analyst-forecast` | 卖方研报 EPS 一致预期 | 每周一 |
| `npm run sync:margin-trading` | 融资融券余额 | 每日 18:00 |
| `npm run sync:etf-flow` | 主流行业 ETF 净申赎 | 每日 18:00 |

> 后端自带 SchedulerService（cron），首次启动后会自动注册每日盘后同步任务，**无需手动每天跑**。

### 2.3 计算因子（数据齐了之后）

```bash
# 算所有 12+ 因子的横截面 z-score / percentile
npm run compute:factors -- --date=2026-06-08

# 计算因子 IC（信息系数），看哪个因子最近有效
npm run compute:factor-ic -- --look-forward-days=20

# 计算因子相关性矩阵（找冗余因子）
npm run compute:factor-correlation
```

完成后到"选股因子"工作区即可看到打分表。

## 3. 选择策略

> 本系统有 13+ 个内置策略，分为 **组合级**（多股选股 + 调仓）和 **per-stock**（按股逐个评估）两种形态。新用户**优先用组合级策略**，因为它们自带 top-N / 行业中性 / 调仓节奏。

### 3.1 策略速查表（13 个组合级 + 4 ensemble）

| 策略 key | 名称 | 适合环境 | 调仓节奏 | 仓位风格 |
|---------|------|---------|---------|---------|
| `multi_factor_alpha` | 多因子 Alpha | 牛市 / 震荡 | 月度 | 均衡 |
| `dragon_head_momentum` | 龙头动量 | 牛市 | 日内 | 高换手 |
| `breakout` | 价量突破 | 牛市 | 日内 | 中等 |
| `game_trader_relay` | 游资接力 | 题材活跃期 | 日内 | 高换手 |
| `linkage` | 行业联动 | 题材活跃期 | 日内 | 中等 |
| `sector_rotation_leader` | 行业轮动龙头 | 牛市 / 震荡 | 周 | 中等 |
| `northbound_follow` | 北向跟随 | 中长期 | 周 | 低换手 |
| `cta100_momentum` | 中证 100 动量 | 牛市 | 月度 | 低换手 |
| `garp` | 价值成长 GARP | 长期 | 半年 | 低换手 |
| `earnings_surprise` | 业绩超预期 | 财报季 | 事件驱动 | 中等 |
| `high_dividend_value` | 高股息价值 | 熊市 / 避险 | 季度 | 低换手 |
| `left_side_reversal` | 左侧反转 | 震荡 / 熊后 | 日内 | 中等 |
| `ensemble` | 多策略融合（meta） | 自适应 | 月度 | 自动 |

**新手建议**：第一周用 `multi_factor_alpha` 跑模拟盘熟悉流程；第二周加入 `ensemble` 让它根据市场环境自动切换。

### 4.3 风控守门员

下单经过 **PaperTradingFacade.placeOrder** → 顺序检查：

1. **PositionLimitGuard**（US-047）：持仓数 ≤ 上限？单股 ≤ 30%？行业 ≤ 30%？
2. **DrawdownCircuitBreaker**（US-049）：组合回撤 ≥ 10% 暂停买入 N 日？
3. **AShareConstraintEngine**（US-014）：涨跌停 / 停牌 / ST / 流动性？
4. **资金 / 持仓数校验**：现金够吗？卖单数量 ≤ 持仓吗？

任一拒单：UI 弹红色 Toast 提示原因（统一来自 `RejectionReason` enum，可读性高）。

## 5. 阅读复盘

> 复盘的目的：**找出胜负的原因**，而不是看绝对盈亏。一笔盈利可能纯靠 beta（大盘涨）；一笔亏损可能源于行业整体回撤。归因报表才是 Alpha 投资者真正应该看的。

## 6. 调参与优化

> 策略不调参就是裸跑。本平台有 **3 套调参工具**：grid search（穷举）、bayesian（智能搜索）、walk-forward（防过拟合）。先用前两个找最优，再用后一个验证不是过拟合。

### 6.3 Walk-forward 验证（必跑！）

**找到最优参数后，一定要用 walk-forward 验证**——否则可能是过拟合：

```bash
npx ts-node src/scripts/walk-forward.ts \
  --strategy=multi_factor_alpha \
  --start=2022-01-01 \
  --end=2025-12-31 \
  --train-months=12 \
  --test-months=3 \
  --optimizer=grid \
  --param top_n=20,30,40,50
```

输出关键指标 **out_of_sample_decay**：

```
Walk-forward summary (12 windows)
─────────────────────────────────────────────
mean_train_sharpe:  2.15
mean_test_sharpe:   1.42
out_of_sample_decay: 0.73   🟢 (< 1.0 = 健康)
─────────────────────────────────────────────
```

- decay < 1.0 🟢 健康，参数可信
- decay 1.0 ~ 2.0 🟡 警告，参数有过拟合嫌疑
- decay > 2.0 🔴 灾难，参数无效，回去重选

## 8. 常见问题（FAQ）

### Q1：登录后首页空白 / 工作区报错？

**A**：90% 是数据未同步。先去 **数据中心** 看看 5 个核心数据源（北向 / 龙虎榜 / 涨停 / 行业流 / 财报）是否绿灯。**所有都未同步** → 回 §2 跑 `npm run sync:*`。

### Q2：策略实验室点"启动新回测"没反应？

**A**：检查后端日志是否有 `Bull queue not connected` 错误。如果是，运行 `docker-compose up -d` 确认 Redis 在跑。

### Q3：回测结果异常好（Sharpe > 5）？

**A**：99% 是 **lookahead bias**（用了未来数据）。Lighthouse：
- 检查回测窗口是否覆盖你计算因子的窗口（不要重叠）
- 检查策略是否在 `evaluate()` 内直接读了未来的 `bar[i+1].close`（应该用 T-1 数据）
- 跑 walk-forward 验证（§6.3）—— 如果 out_of_sample_decay > 2，几乎确定过拟合

### Q4：模拟盘下单失败 "无法解析股票代码"？

**A**：本系统统一用 **6 位数字 + 交易所后缀**（`600519.SH` / `000001.SZ`）。如果你只输入了 `600519`，UI 会自动补全；CLI 调用必须显式带后缀。

### Q5：今日作战 Card 显示"X 缺数据"？

**A**：US-018 的 per-block error fallback —— 某个策略的 DataSource 报错时只该 Card 显示警告，不影响其他策略。看 Card 顶部红色 Alert 内的具体错误（通常是某个数据源未同步）。

### Q6：因子权重该怎么调？

**A**：3 个方法：
- **静态**：经验值 30/20/20/15/15（动量/流动性/成长/质量/价值）
- **等权**：让所有 5 因子 0.20，做对照组
- **IC-weighted**（US-081）：让系统按近 60 日 IC 自动加权 — 这是推荐做法

在策略详情页 → 编辑 → `weight_mode: 'ic_weighted'`。

### Q7：模拟盘的 PnL 是真实价能复制吗？

**A**：是。本平台模拟盘的成交价 = T+1 开盘价（默认 `execution_timing: 'next_open'`）+ 动态滑点（按换手率分段 0.2%-0.36%）+ 完整费率（万 2.5 佣金 + 千 1 印花税 + 万 0.1 过户费）—— 比绝大多数券商 demo 账户严格。一年 Sharpe ≥ 1.5 的策略接真盘后实际表现下降一般 < 30%。

### Q8：AI Copilot 给的建议要听吗？

**A**：建议但**不要照搬**。Copilot 是基于历史 IC / 历史回测的统计模型，市场环境一旦变化（例如从 bull 切到 bear）历史 IC 失效。推荐用法：
1. 用 Copilot 生成 2-3 个候选参数组
2. 每个跑 walk-forward 验证（§6.3）
3. 选 decay < 1.0 的那个

### Q9：cron 任务怎么改 / 关？

**A**：所有定时任务在数据库表 `scheduled_tasks` 里，UI 在 **账号设置 → 系统调度** 可查看 / 暂停。**不要**直接改后端代码——cron 设计是热配置（启动时从 DB 读）。

### Q10：数据同步占满磁盘？

**A**：跑 US-097 清理脚本：

```bash
# dry-run 看会清多少
npm run cleanup:old-data

# 真删
npm run cleanup:old-data -- --confirm
```

默认清理：90 天前的回测、180 天前的日志、30 天前已读告警。每周日凌晨 3:00 cron 自动跑。
