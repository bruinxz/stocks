## -1. 术语表 (股票小白必读)

这份文档里有很多"股票黑话", 先在这里一次性讲清楚。看正文时遇到词回来查。

### -1.1 交易 / 组合基本词

| 词 | 白话解释 |
|---|---|
| **组合** | 你所有股票加起来的整体, 就是你账户里那一堆股票的总和 |
| **仓位 / 持仓** | 你手里持有的股票 (相对于全部资金而言的比例) |
| **单仓上限** | 一只股票最多能占你总资金的多少 (例: 15% 就是 30 万里最多 4.5 万买一只) |
| **建仓 / 加仓** | 买入 |
| **平仓** | 卖出全部 (清掉这只股票) |
| **减仓** | 卖出一部分 (还留一些) |
| **止损** | 亏到一定程度强制卖 (例: 亏 7% 就砍, 不让继续亏) |
| **止盈** | 涨到一定程度强制卖 (例: 涨 20% 就卖, 落袋为安) |
| **换手 / 调仓** | 卖旧的买新的 (把持仓从 A 换成 B) |
| **再平衡** | 定期检查, 把偏离目标的仓位调回目标比例 |
| **回撤** | 从最高点跌下来的幅度 (例: 100 万涨到 120 万又跌回 90 万, 回撤 = 25%) |
| **年化收益** | 一年下来赚多少% (例: 12% 就是 100 万变 112 万) |
| **Sharpe** | 收益质量分, 高 Sharpe = 收益高且波动小 (稳赚), 低 Sharpe = 忽赚忽亏 |

### -1.2 股票类型 / 工具

| 词 | 白话解释 |
|---|---|
| **A 股** | 中国大陆股票 (上海 + 深圳 + 北交所) |
| **ETF** | 一篮子股票打包, 一手买 = 同时买几十只成分股, 分散风险。像基金但能像股票一样交易 |
| **宽基 ETF** | 跟踪大盘指数的 ETF (沪深 300 / 中证 500 / 创业板), 代表整个市场 |
| **行业 ETF** | 只买某个行业的 ETF (半导体 / 医药 / 银行) |
| **主题 ETF** | 追热点的 ETF (AI / 光伏 / 新能车), 波动大 |
| **成分股** | 一个 ETF / 指数里包含的具体股票 (沪深 300 = 300 只股票, 那些股票就是成分股) |
| **T+1** | A 股规则: 今天买的明天才能卖 (锁一天) |
| **涨停 / 一字板** | A 股股价一天最多涨 10% (创业板 20%), 到顶叫涨停; "一字板" = 全天从开盘就顶格, 挂不进去买单 |
| **集合竞价** | 开盘前 9:15-9:25 集中撮合, 9:25 一次成交出开盘价 |
| **限价单 / 挂单** | 你指定"最多这价买", 到价才成交, 不到价挂着 |

### -1.3 因子 / 策略词

| 词 | 白话解释 |
|---|---|
| **因子** | 挑股票的一种规则 / 特征。学术研究证明某些因子长期跑赢市场 |
| **Value (价值)** | 挑便宜的股票 (PE / PB 低, 股息率高) —— "买打折的" |
| **Quality (质量)** | 挑赚钱能力强的股票 (ROE 高, 利润稳定) —— "买好公司" |
| **LowVol (低波)** | 挑波动小的股票 (股价不忽上忽下) —— "买稳的" |
| **Momentum (动量)** | 挑最近涨得好的股票 —— "追涨" (A 股不好用, 会追高被套) |
| **PE / PB / ROE** | 财务指标。PE = 市盈率 (股价/每股利润), PB = 市净率 (股价/每股净资产), ROE = 净资产收益率 (公司赚钱效率) |
| **z-score** | 标准化分数, 让不同量纲的因子能加权求和 (例如把 PE 和 ROE 变到同一尺度) |
| **因子轮动** | 定期按因子分排序, 挑分高的换掉分低的 (机械化选股, 排除主观情绪) |
| **主题事件 / 题材** | 短期热点炒作 (AI 火了 → 相关股一起涨, 冷了 → 一起跌) |
| **回测** | 用历史数据模拟策略, 看"如果当时这么做, 现在赚多少" |
| **实盘** | 真金白银下单 |
| **纸面 / paper trading** | 模拟盘 (下单信号进系统但不真下钱), 用来试新策略 |

### -1.4 系统词 (本项目专用)

| 词 | 白话解释 |
|---|---|
| **信号 (Signal)** | 一条"该干啥"的建议: (哪只股, 买还是卖, 什么时间, 有多信心) |
| **detector** | 生成信号的程序模块 (例如 ThemeFermentationDetector = 题材发酵探测器) |
| **管线 / pipeline** | 一条信号从生成到入库的流水线; 我们目前有 3 条并存 |
| **B-fusion 管线** | 系统里的一条信号流水线 (95 笔 0% 胜率的祸首), 融合了 20 个同类策略结果, 后面要删 |
| **confidence (置信度)** | 该信号历史胜率 (例: 该 detector 过去 90 天报的信号里, 65% 后来真的赚了 → confidence = 0.65) |
| **EV (期望值 gate)** | 期望值门槛, 只有"预期收益 > 门槛"才下单。EV = 胜率 × 平均赚 − (1-胜率) × 平均亏 |
| **主线 / 核心** | 系统主战场 (占资金 70%), 稳中求进. **"核心-卫星 (Core-Satellite)"** 是投资界经典组合结构 — 想象太阳系: 核心 = 太阳, 稳定发光, 是收益主要来源. 这里指 70% ETF 因子部分. |
| **卫星** | 围着核心转的辅战场 (占资金 20%). 比喻上是围绕太阳的行星: 数量少、波动大、受核心引力约束 (硬边界 ≤20%). 这里指 20% 题材事件驱动部分, 可能亏可能高收益, 严控上限. **"卫星累计亏损"** = 那 20% 里所有股票加起来在一段时间的总亏损. |
| **战略镜子** | 每月自我审视机制, 用 6 道题看清"这个月赚亏归因是什么" |
| **override** | 用户不听系统建议手动强行下单 |
| **regime** | 市场状态 (牛市 / 熊市 / 震荡市) |
| **cooldown 冷却期** | 触发某条件后一段时间不许再下单 (例: 一个题材刚亏了, 30 天不许再碰同题材) |
| **PR-x** | 我们做过的 PR (Pull Request, 代码改动) 编号, 例如 PR-L = 紧急停损那次改动 |

## 0. 全局约束

### 0.1 正确性优先准则

**大白话**: 判断一段代码要不要留下, 看两件事——**思路对不对** 和 **有没有在用**。

判断代码留 / 删用二维矩阵 (思路对错 × 用没用):

| 思路 | 在用 | 处置 |
|---|---|---|
| 正确 | 在用 | 保留 |
| 正确 | 没在用 | 可以删 (留着是 noise) |
| 错误 | 在用 | 改思路或重写 |
| 错误 | 没在用 | 删 |

"干净" = 思路正确合理 + 有在用。
代码多 ≠ 脏, 烂思路才是脏。

**优先级**: 正确 > 快, 思路对 > 代码量小, 不图快图对。

### 0.2 例外 (必须保留, 即便思路待评)

**大白话**: 即使思路暂时讲不清, 有两类东西也不能动——一是**保命的**, 二是**大家都要用的公共设施**。

- PR-L 紧急停损 (实盘 win% 转正前) —— 相当于紧急刹车, 有 bug 也得留着别拆
- 公共基础设施 (DB / cron 框架 / 日志 / monitoring) —— 全系统都依赖, 动一个死一片

### 0.3 决策前置

**大白话**: 想写新代码前, 先在这份文档里说清楚"我为啥要写这个", 得到自己 / AI 确认再动手。防止边写边改思路造成的浪费。

- 决定要写代码前, 先在文档中写出该模块 "思路对不对" 的判断, 通过后再执行

### 0.4 方案选择准则 (规范 > 快)

**大白话**: 遇到方案选择时, AI 应默认选**更规范 / 更长期 / 更有扩展性**的那一个, 而不是"哪个更简单快"。今天省 30 分钟, 半年后拆重构要花 3 天, 是净亏。

**判断顺序**:
1. **规范优先**: 有行业标准 (e.g. Sequelize migration / soft delete / composite index) 就用标准, 不自己发明
2. **长期优先**: 6 个月后 (数据量 10x / 用户 override 500 次 / 卫星永久停) 该方案能不能扛住
3. **扩展性优先**: 未来加维度 (加因子 / 加 detector / 加 regime 类型) 时改动是"加字段"还是"重建表"
4. **只有当以上三项打平**才比较开发成本

**例子**:
- ID 用 `<type>-<key>-<yyyymmddhhmm>` 而不是 `nanoid()` → 更规范, 人类可读, 便于排查 (规范 > 快)
- BUY-SELL 每次配对**新建独立 lifecycle_id**, 而不是"多次加仓复用同一 id + lot_seq" → 每笔独立更容易扩展"分批止盈"、"部分平仓" 而不用改 schema (扩展性 > 简洁)
- DB 存 timestamp 用 `TIMESTAMPTZ` 不用 `TIMESTAMP` → 时区问题一次到位

**反例 (禁止)**:
- "现在只有一个 admin, 权限不用做" → 未来加人时权限散在每个 controller, 重构成本极高
- "缓存 15 分钟, 数据不新鲜没关系" → 未来实盘触发时靠这个数据决策, 停在 15 分钟前的错数据一次亏几万

## 1. 起因

**大白话**: 6 周做了一大堆事, 但两件事同时成立——**系统在亏钱**, 同时**还在不停加新东西**。这不对, 得先停下来看清楚问题在哪。

系统在 6 周内积累 30+ PR, 6 条战线并行 (数据 / detector / UI / 通知 / 风控 / bug fix)。
两个矛盾事实:

| 事实 | 数据 |
|---|---|
| 系统在亏钱 | 实盘 95 笔平仓 win% = 0%, avg -8.04% (95 单全亏, 平均一单亏 8%) |
| 信号在被加 | 6 周新增 13+ detector / 122 战法 / 6 条战线并行 |

深度诊断发现:
- prod 信号表**实际只 3 个 source_type 在写** (虽然名义上有 13 个 detector, 但真正往数据库写信号的只有 3 个模块)
- **95 笔 0% 实盘全来自 `QuantFusionService`** (B-fusion 管线), 该管线用 20 个同质化趋势策略做"伪共识" (20 个策略都是"追涨"套路, 它们全说"买" 其实只是一种意见, 不是 20 种)
- **confidence 是规则封顶** (fusion_score ≥ 96 几乎必然, 失去概率含义) —— 系统显示"96% 置信", 实际是 20 个策略投满票时封顶数值, 跟真实胜率无关
- **A 股学术证据**: 题材短反转 > 动量 (追热点通常追在顶部, 冷门反而反弹), 主题 ETF 5 年跑输基准 30%, 散户系统性亏损

## 2. 产品骨架

### 2.1 骨架

**大白话**: 系统只做一件事——**告诉你什么时候该买卖什么股票**。这个建议现在给你人自己判断, 以后可以让系统自动执行。同时用历史数据回测, 检查"这些建议靠谱不"。

> **一个信号源 → 两个出口 → 回测验证可信度**
>
> 出口 A (现在): 给用户, 用户拍板
> 出口 B (后期): 自动执行
> 同一套信号回灌回测, 回答"这信号可不可信"

隐含契约 (**修正**, 原表达"信号=回测=实盘"太强):

> **同一 signal 契约 + 同一执行假设 + 同一归因口径; 回测/纸面/实盘偏差可解释、可度量、可收敛.**

翻译成大白话: 三者不追求绝对等号 (A 股涨跌停 / 集合竞价 / 滑点 / ETF 折溢价 / 数据修订 / 政策结构断点决定了实盘永远和回测有偏差), 但要求:
1. **同契约** — 三者读同一份 Signal 结构 (§2.2), 不能纸面下单用一套字段实盘用另一套
2. **同执行假设** — 回测中的成本、滑点、成交时点必须模拟实盘的执行规则 (§4.1 集合竞价改 9:40 VWAP)
3. **同归因口径** — 每笔 PnL 分解 = 信号 alpha + 执行滑点 + 折溢价 + 成本, 三处用同一分解表
4. **偏差可度量** — 每周输出 `live-vs-backtest drift report`, 包含 slippage attribution
5. **偏差可收敛** — 若 drift 单向持续 > 30 天, 触发 §10 降级 review

目前不成立 (回测 48% 胜率, 实盘 0% 胜率, 说明回测在骗人)。让偏差**可解释可收敛**是北极星。

### 2.2 信号原子定义

**大白话**: 每条"该买/该卖"的建议长成下面这个数据结构。5 个核心字段是必填 (谁, 买还是卖, 什么时间, 多信心, 谁给的建议), 其他字段自动化系统会补。

```typescript
type Signal = {
  // 核心 5 字段
  symbol: string;                              // 股票代码, 例如 "600519" (茅台)
  action: 'BUY' | 'SELL' | 'TARGET_WEIGHT';    // 买 / 卖 / 调到目标比例 (ETF 用)
  timestamp: Date;                             // 什么时候发出的
  confidence: number;                          // 该 detector 历史胜率, 0-1 之间
  source_detector: string;                     // 谁给的建议 (方便追责)

  // 生命周期
  lifecycle_id?: string;       // 用来把"买这只"和后来"卖这只"配对起来
  theme_id?: string;           // 卫星题材专用: 属于哪个题材 (AI / 光伏)
  rebalance_id?: string;       // 核心 ETF 每月再平衡时给的组标识
  target_pct?: number;         // TARGET_WEIGHT 时: 目标仓位%

  // 自动化字段 (自动化层填充)
  expected_value?: number;              // 预期收益 (EV, 用胜率×平均赚算出来)
  recommended_size_pct?: number;        // 建议买多大 (占总资金%)
  entry_price_strategy?: 'auction_open' | 'observe_15min' | 'skip';  // 咋买: 开盘直接买 / 观察 15 分钟 / 别买
  stop_loss_pct?: number;               // 跌到这个%就止损
  take_profit_pct?: number;             // 涨到这个%就止盈
  cooldown_until?: Date;                // 冷却到什么时候
  gate_pass?: boolean;                  // 通没通过 EV 门槛
  gate_reason?: string;                 // 通过 / 拒绝的原因文字说明
}
```

**关键设计**:
- **confidence 是概率, 不是得分** (之前系统里是"打分封顶", 现在必须是"过去 90 天真实胜率")
- **source_detector 让每条信号可追责** (哪个模块建议错了看得到)
- **SELL 是配对平仓, 不是看跌扫描** (系统不会主动扫全市场找"该卖空的", SELL 只针对"我已经持有的" 说什么时候卖)
- **自动化和用户拍板消费同一套信号 + 同一套 gate** (人机同源, 不搞两套逻辑)

### 2.3 3 个 ID 的规范

**大白话**: Signal 结构里有 3 个 ID 字段, 分别用来把相关信号关联起来。下面定义"谁生成 / 什么时候清 / 数据库怎么存"。

**通用格式约束**:
- 全部用**人类可读结构** `<type>-<key>-<yyyymmdd[hhmm]>`, 不用随机 UUID / nanoid
- 便于日志排查、数据库直查 (`WHERE lifecycle_id LIKE 'theme-600519-%'`)
- 遵循 §0.4 "规范 > 快"

#### lifecycle_id — BUY-SELL 配对

**用途**: 把一次进场 (BUY) 到出场 (SELL) 绑定, 方便算完整 PnL

| 维度 | 规则 |
|---|---|
| 生成时机 | BUY 信号发出瞬间 (SignalRouterService) |
| 格式 | `<detector>-<symbol>-<yyyymmddhhmm>`, 例: `theme-600519-202607011425` |
| 加仓怎么办 | **每次 BUY 都是新的 lifecycle_id** (独立配对). 不复用+lot_seq. 简化统计, 未来"分批止盈"、"部分平仓" 都直接每次新 id 而无需改 schema (§0.4 扩展性优先) |
| SELL 配对 | ①同 detector 主动 SELL: 复用最近未平仓 BUY 的 lifecycle_id; ②止损/止盈/时间到期 SELL: 系统查最近未平仓 BUY 反填 |
| SELL 找不到 BUY | 不静默丢弃 → 记入 `orphan_sells` 表, 每日 review 人工兜底 |
| 清除 | 永不清除 (统计需要历史) |
| DB 索引 | `CREATE INDEX idx_signals_lifecycle ON ai_investment_signals (lifecycle_id)` + `recommendation_trade_outcomes` 冗余同步一份用于回填 |

#### rebalance_id — 月度再平衡组标识

**用途**: 一次月度再平衡触发的多条 signal (卖 A / 买 B / 买 C) 绑同一组, 便于把这一批 PnL 汇总看再平衡效果

| 维度 | 规则 |
|---|---|
| 生成时机 | `ETFRotationService` 月度触发时生成一次 |
| 格式 | `rebalance-YYYY-MM`, 例: `rebalance-2026-07` |
| 一批共享 | 同一次 rebalance 触发的**所有** signal 用同一 id |
| 同月二次触发 | 紧急再平衡时加序号 `rebalance-2026-07-2` (少见 case) |
| 清除 | 永不清除 |
| DB 索引 | `CREATE INDEX idx_signals_rebalance ON ai_investment_signals (rebalance_id) WHERE rebalance_id IS NOT NULL` (部分索引省空间) |

#### theme_id — 卫星题材标识

**用途**: 一个题材 (AI / 光伏) 可能触发多只题材股信号, 把它们关联起来才能算"AI 这一波总共赚了多少"

| 维度 | 规则 |
|---|---|
| 生成时机 | `ThemeFermentationDetector` 探测到"启动"阶段时 |
| 格式 | `<industry_slug>-<launch_date>`, 例: `ai-computing-20260615` |
| 多只股共享 | 同题材下所有相关个股 signal 复用同一 theme_id |

## 3. 最终锁定

**大白话**: 经过多轮讨论 + 学术证据 + 外部审计, 最终定下来是这么一个组合结构:

```
真目标      = 组合年化 10-15% (持续, 不要短期高然后回吐)
                → 说人话: 30 万一年赚 3-4.5 万, 别指望暴富, 也别忽赚忽亏

主线结构    = 核心 70% (ETF 因子) + 卫星 20% (题材事件) + 现金 10%
                → 70% 稳稳赚, 20% 博高收益 (可能亏但控住), 10% 应急/收利息

资金        = 10-50 万 (以 30 万为基准计算)
决策方式    = 用户拍板 (核心每月看一次, 卫星按事件看)

单仓上限    = ETF 15% / 题材股 5% (卫星更严, 因为个股崩得快)
最大持仓    = 4-5 只 ETF + 3-4 只题材股 (总 7-9 只)
                → 太多管不过来, 太少不分散

override    = 允许, 但走审计流程 (二次确认 + 写理由 + 入库)
                → 系统说"别买"你还是要买, 得写理由存档, 亏了责任在自己
```

数学核算 (30 万):
```
乐观: 12.6% 组合年化 (核心 12% + 卫星 20%)  → 30 万 → 33.8 万
中性: 8.2%  组合年化 (核心 10% + 卫星 5%)   → 30 万 → 32.5 万
悲观: 4.8%  组合年化 (核心 8%  + 卫星 -5%, 硬边界触发前会停) → 30 万 → 31.4 万
```

**证据锚定** (Fang & Olteanu-Veerman 2020, de Groot 2021, 学术论文):
- A 股 Value / Quality / LowVol 有稳定溢价 (10-18% 长期年化), 意思是过去 20 年这么做真的赚
- Momentum (追涨) 在 A 股有争议 (Hsu 2018 论文: 失败), 所以只给 10% 权重, 谨慎测试

**stance (立场)**: 换, 但要证据。今天已兑现一次 (从原来"题材主打"→ "ETF + 题材混合", 因为学术证据显示纯题材策略在 A 股散户手里长期跑输)。

## 4. 主线设计

### 4.1 核心 70% — ETF 因子轮动

**大白话**: 主战场用**因子轮动 ETF**——每个月按 4 个因子 (估值 / 质量 / 低波 / 动量) 给几十只 ETF 打分, 挑分最高的 4-5 只买入, 分数掉出前 6 名的卖掉。这是机械化、无情绪的方法, 学术研究证明长期能跑赢市场。

**⚠️ 证据迁移警告**: A 股股票因子有效 ≠ ETF 能稳定捕获同等 alpha. ETF 会受**跟踪误差、成分股调整、规模流动性、折溢价、开盘价差、上市时间、幸存者偏差**影响. 因此:
- **回测数据要求** (P0 硬约束):
  - 用真实可交易 ETF 历史价格 (含分红调整), 禁止用今天的 ETF 池反推历史
  - Point-in-time 成分股/财务数据 (2023-03 的因子分只能用 2023-03 当时可得的成分和财报)
  - 真实交易成本 (手续费 0.13%×2 + 冲击成本 0.1-0.3%/8)
  - 剔除上市不足 6 个月、日均成交额 <2000 万的 ETF (流动性 gate)
  - 保留已退市/合并 ETF 的数据段 (避免幸存者偏差)
- **验收指标** (Wave 2 达标才允许 Wave 3 上线):
  - 成本后年化 ≥ 10%
  - 最大回撤 ≤ 25%
  - 换手率 ≤ 200%/年
  - 成本翻倍压力测试后 alpha 仍 > 0

**参考来源**:
- S&P Global, Examining Factor Strategies in China's A-Share Market
- MSCI, Are You Really Capturing the Right Factors? China A-Share Factor Investing

**候选 ETF 池 (46-63 只)**:

| 组 | 数量 | 内容 |
|---|---|---|
| 宽基 | 8-12 | 300 / 500 / 1000 / 创业板 / 科创 50 / 深证 100 / 上证 50 (跟踪大盘的) |
| 风格因子 | 6-10 | 红利 / 中证红利 / 高股息 / 300 价值 / 低波红利 / 500 质量 (已经做好因子筛选的 ETF) |
| 行业 | 20-25 | 消费/医药/科技/金融/军工/新能源/半导体/银行/券商/有色 (单行业 ETF) |
| 主题 | 8-10 | AI/芯片/5G/新能车/光伏/医疗器械 (慎用, 用于测试动量因子) |
| 债券/商品 | 4-6 | 国债/短融/黄金 (对冲用 + 闲置现金去处) |

**因子权重 V0** (V0 candidate, Momentum 首版降级 shadow):

| 因子 | 权重 V0 | 状态 | 计算 |
|---|---|---|---|
| Value (估值) | **0.40** | 主 | PB 倒数 + PE-TTM 倒数 + 股息率, z-score 加权 |
| Quality (质量) | **0.30** | 主 | 成分股平均 ROE + 利润增长稳定性 (5 年利润波动小) |
| LowVol (低波动) | **0.30** | 主 | 过去 60 日日收益波动 × (-1) 与 20 日波动 × (-1) 加权 |
| Momentum (动量) | **0.0 (shadow)** | 观察, 不入实盘权重 | 过去 20 日累计收益, **仅记录并 walk-forward 验证** |

**关键修订**:
- Momentum 从 0.10 降到 **0.0 (shadow only)** — Hsu et al. (2017) 论文明确显示 A 股 short-term momentum 可能反转; 20 日动量与题材卫星热点逻辑重叠, 一旦上核心会把主线拖向短线化
- Value 从 0.35 → 0.40, LowVol 从 0.25 → 0.30 — 吸收 Momentum 的 10% 权重, 加权到已验证的两个因子 (MSCI 2025 指出 A 股高股息 / 低波比全球更突出)
- **权重是 V0 candidate**, 不是已验证结论. 允许在**保守权重网格** {(0.4/0.3/0.3), (0.35/0.35/0.3), (0.5/0.25/0.25)} 上做敏感性验证, **禁止追求最优参数** (会过拟合)
- 输出: 每组权重的**换手率、最差年份表现、成本后 alpha**, 若敏感性差异 < 2% 年化则采用最保守组

**参考来源**:
- Hsu, Viswanathan, Wang, Wool (2017), Anomalies in Chinese A-Shares (SSRN 2955144)
- MSCI 2025 China A-Share Factor Investing
- CAIA, Factor Investing in the China A-Share Market

综合分 = 各因子 z-score × 权重, 加起来 (Momentum 单独存 shadow 分, 不参与排名)

**再平衡** (什么时候换股):
- 频率: 月度 (每月最后交易日 22:00 计算, **次月第一交易日 9:40 后分批限价/VWAP 执行**)
- 持仓: top 4-5 只 ETF, 单只 12-15%, 核心总仓位 60-70%
- 换仓逻辑:
  - 排名滑出 top 6 → SELL (掉出前 6 卖掉)
  - 排名进入 top 4-6 → BUY (新进入前 4-6 买入)
  - 排名保持 → 持有不动 (还在 top 就别折腾)

**执行细节** (集合竞价 9:25 太粗, 会吃开盘价差、折溢价异常、流动性噪音):

原方案 "9:25 集合竞价" 会吃开盘价差、折溢价异常、流动性噪音, 侵蚀本就不厚的因子超额. 改成:

| 阶段 | 时点 | 方式 |
|---|---|---|
| Pre-check | 9:25 - 9:35 | 观察集合竞价出价、盘口深度、ETF vs 净值折溢价. 若折溢价 > 0.3% (溢价过高) → 推迟到 9:45 复评 |
| Split execution | 9:40 - 11:00 | 分 3-4 笔限价单 (限价 = 上一分钟均价 ± 0.05%), 每笔间隔 10-20 分钟 |
| VWAP fallback | 11:00 - 14:00 | 若未成交完, 剩余部分用 VWAP 算法或以当天 VWAP 为参考的限价 |
| Cutoff | 14:30 | 未完成部分**次日续做**, 不追高 |

**执行 gate** (以下任一触发, 该 ETF 当日 skip):
- 折溢价绝对值 > 0.5%
- 盘口买一/卖一距离 > 0.3%
- 当日成交额 < 前 20 日均值 × 30%

**回测要求**: 回测必须模拟 open / next-open / 9:40 / VWAP **四种执行价**, 输出**执行敏感性表** (哪种执行方式导致 alpha 差异多大).

**SELL 机制**: 只有月度再平衡触发, **不设单笔止损止盈**。ETF 波动小, 月度调仓足够风控。组合级 PR-L (整体大跌熔断) 保留。

### 4.2 卫星 20% — 题材事件驱动

**大白话**: 辅战场用**题材事件驱动**——系统监控市场热点 (AI / 光伏这种题材), 探测到某题材"启动"或"爆发"就买入相关个股, "退潮"就卖。风险大但可能有高收益, 所以**严格控上限**——单只股最多 5%, 整个卫星最多 20%, 亏太多直接冻结。

**依托**: `ThemeFermentationDetector` (题材发酵探测器 PR-O5) — 但**必须先做数据链修复** (见 §6.2)。

**触发** (BUY, 什么时候买):
- Detector 报"启动"或"爆发"阶段 (系统探测到某题材正在酝酿 / 爆发)
- 该题材未在冷却期 (不是刚亏过又来送死)
- 卫星总仓位未达 20% 上限

**触发** (SELL, 什么时候卖):
- Detector 报"高潮"或"退潮" (题材已到顶部或开始冷)
- 单笔 -7% 止损 (亏 7% 强制卖)
- 单笔 +20% 止盈 (赚 20% 落袋)
- 持仓满 21 个交易日 (硬时间, 到期无论盈亏都卖, 因为题材一般 3-4 周就冷了)

**仓位**:
- 单只题材股上限 5% (严于 ETF 的 15%, 因为个股崩得快)
- 目标持仓 3-4 只题材股
- 卫星总仓位上限 20%

**卫星硬边界** (防止无限吞钱):

```
□ 卫星总仓位 ≤ 20% (不允许扩)
□ 卫星【60 天滚动窗口】累计亏损 > 组合 5% → 卫星冻结 30 天, 只保留核心
    (30 万里, 过去 60 天卫星总亏 > 1.5 万 就冻结)
    起算方式: 每日盘后计算 (今日 - 60 天, 今日] 区间内所有 SELL 已实现 PnL
              + 期末未平仓的浮亏, 加起来 < -5% × 组合总资产 → 触发
    冻结解除后: 起算点不重置, 依然滚动 60 天窗口
□ 【自然月】连续 3 个月卫星月度 alpha < 0 → 卫星永久停止, 资金转入核心
    (alpha = 卫星月度 PnL% - 沪深 300 月度涨跌%)
    严格连续: 中间任何 1 个月 alpha ≥ 0 都重置计数
    冻结月计入: 冻结期间强制持仓不动, 仍算月度 alpha (通常为 0 或轻微负)
□ 单只题材股【自持仓成本】-15% (深止损, 波动大) → 强制平仓
```

**卫星是探索沙盒, 核心永远是主战场**。别把辅战场当主力用。

**大白话**: 剩下 10% 别闲着, 分两份——一半留应急 (家里急用), 一半买最保守的国债 ETF 或货币基金吃个 2-3% 的年利息, 比银行活期多。

### 4.4 卫星题材股 T+1 Entry 规则

**大白话**: A 股规则今天买明天才能卖, 且个股有涨停 (最多涨 10%)。**这条规则只针对卫星题材个股** (§4.2)—— 核心 ETF (§4.1) 不受此规则约束, ETF 无涨停打不进问题, 直接集合竞价。如果系统今天说该买某题材股, 但收盘涨停了, 明天开盘可能一开就涨 5-10%, 追进去容易被套。这里定义了几种情况下怎么应对。

**适用范围**: 只针对 §4.2 卫星题材股. 核心 ETF 直接集合竞价 entry, 忽略此规则.

针对卫星题材股的涨停 / 高开问题:

```
if 信号 T 收盘涨停 (今天到顶了):
  → 允许"限价追高 3%" (T+1 集合竞价挂"高开 3% 以内成交"的限价单)
     打得进 → 成交, 进场
     打不进 (一字板 = 全天挂涨停, 抢不到) → T+2 观察, 继续涨停则放弃, 开板 (跌下涨停) 则追入

elif T+1 高开 > 5% (明天开盘一下涨 5% 以上):
  → 观察 15 分钟后决定 (可能是炒作短线冲高, 15 分钟内往往回落, 等等看)

elif T+1 高开 < 3% (明天开盘涨得不多):
  → 集合竞价 entry (开盘直接买)
```

(核心 ETF 不受此规则约束, 已在标题上方说明.)

## 5. 自动化 + confidence

### 5.1 confidence 模型 (Wilson lower bound + 完整校准)

**大白话**: 每条信号旁边要显示"置信度 X%", 但**不能只用简单胜率**——样本少时 40%/55% 可能只是噪音, 且忽略盈亏比、回撤路径、成本, 用点估计直接 sizing 会**系统性过度自信**. 因此:
1. **confidence 用 Wilson 下界** (置信度 90%), 不用裸胜率
2. 同时存 5 个校准指标: `n_samples / avg_win / avg_loss / profit_factor / brier_score`
3. UI 显示时给出 reliability bucket ("样本少置信度差", "样本足胜率稳"), 让用户看到样本量, 而不是被光鲜的百分比误导

**核心公式**:
```
n = detector 过去 90 天信号数
k = 其中赚钱的信号数
p_hat = k / n  # 裸胜率
confidence = Wilson_lower_bound(k, n, α=0.10)  # 90% 置信下界
```

Wilson 下界公式:
```
z = 1.645  (α=0.10, 单侧 90%)
denom = 1 + z²/n
center = (p_hat + z²/(2n)) / denom
margin = z × sqrt(p_hat×(1-p_hat)/n + z²/(4n²)) / denom
confidence = center - margin
```

**举例**:
- Detector A: n=100, k=55 → p_hat=55%, confidence (Wilson lower) = **47.5%**
- Detector B: n=10,  k=6  → p_hat=60%, confidence (Wilson lower) = **34.6%**

裸胜率 B 更高, 但 Wilson 下界表明 B 样本太少不可信, A 更靠谱. 系统按 confidence (Wilson) 排序.

**同时存的 5 个校准指标**:

| 指标 | 定义 | 用途 |
|---|---|---|
| `n_samples` | 90 天内该 detector 结算样本数 | 小于阈值 (< 20) 时降权或只跑 paper |
| `avg_win_pct` | 赚钱信号的平均收益 % | EV 公式用 (§5.2) |
| `avg_loss_pct` | 亏钱信号的平均亏损 % (绝对值) | EV 公式用 |
| `profit_factor` | Σ 盈利 / Σ 亏损 | > 1.5 才算稳定盈利策略 |
| `brier_score` | 概率校准分数 (0=完美, 0.25=瞎猜) | 每周输出 reliability diagram, 越低越好 |

**Reliability bucket** (UI 展示):

| Wilson 下界 | n_samples | 展示标签 | 是否允许下单 |
|---|---|---|---|
| ≥ 45% | ≥ 30 | 🟢 "样本充足, 胜率稳定" | 是, 全权重 |
| 30-45% | ≥ 30 | 🟡 "样本充足, 胜率中等" | 是, 但 sizing × 0.7 |
| ≥ 45% | 20-29 | 🟡 "样本偏少, 建议观察" | 是, sizing × 0.5 |
| < 30% 或 n < 20 | - | 🔴 "样本不足或胜率差" | **纸面模式**, 不进 EV gate |

**数据源**: `recommendation_trade_outcomes` (数据库表, 存了每条信号的实际结果) 按 source_type (哪个模块给的) group by

**窗口**: (signal_date - 5 天 - 90 天, signal_date - 5 天), 5 天滞后因 forward_return (未来 5 天收益) 需 5 天才能结算

**缓存**: 每 detector 每天算一次, 5 指标全刷新

**三条管线** (A-market / B-fusion / C-bullish) 全部改用此 service, 不再用 score 当 alias

**服务**: 新建 `ConfidenceCalibrationService` (专门算 Wilson + 5 校准指标的模块)

**冷启动 (新 detector 没历史数据咋办)**:
- n < 20 时**默认纸面模式** (不进 EV gate, 不下实盘), 累积样本
- 参考同类 detector prior 时明确标注 "prior from `xxx-detector`", 不能骗自己

**Regime 分层**: 不同市场状态 (牛/熊/震荡) 下同一 detector 表现差异大, 因此:
- confidence 按 regime 分别计算 (`confidence_bull` / `confidence_bear` / `confidence_range`)
- 当前 regime 判定用沪深 300 60 日均线斜率
- 使用时取当前 regime 对应的 confidence, 而不是全局混合

**必然滞后 5 天**: UI 显式标注 "Confidence 38% (Wilson lower, n=45, 基于 04-01 至 06-25), 最近 5 天尚未结算"

**参考来源**:
- scikit-learn Probability Calibration (Brier score, reliability diagram)
- Bailey et al., Probability of Backtest Overfitting

### 5.2 Gate 分层

**大白话** (**修订**): "ETF 核心不用 EV gate" **不等于** "ETF 核心不用 gate". 月度因子排名只解决 "买哪个" 的问题, **不覆盖数据缺失/流动性/折溢价/组合风险/执行成本/PR-L 熔断** 这些执行风险. 因此把 gate 分成 4 层, ETF 核心可跳过卫星专用的 **EV gate**, 但必须过其他 3 层.

**Gate 4 层结构**:

| 层 | 名称 | 检查内容 | ETF 核心 | 卫星题材 |
|---|---|---|---|---|
| L1 | `eligibility_gate` | 数据完整性 / 池成员 / 停牌 / 流动性 / 上市时间 | ✅ 必过 | ✅ 必过 |
| L2 | `risk_gate` | 单仓上限 / 单板块上限 / 组合回撤 / PR-L 熔断 | ✅ 必过 | ✅ 必过 |
| L3 | `cost_gate` | 换手率 / 冲击成本 / 折溢价 / 双边成本 | ✅ 必过 | ✅ 必过 |
| L4 | `ev_gate` | 期望值 > 门槛 (胜率 × 平均赚 - (1-胜率) × 平均亏) | ⛔ 跳过 (月度因子排名替代) | ✅ 必过 |

**具体阈值**:

**L1 eligibility_gate**:
- 上市 ≥ 180 天
- 日均成交额 ≥ 2000 万 (过去 20 日均)
- 当前非停牌
- 池成员 (核心 = ETF 池, 卫星 = 题材池)
- 数据完整性: 过去 90 日无 > 5 个交易日缺失

**L2 risk_gate**:
- 单仓上限 (核心 ETF 15%, 卫星题材 5%)
- 单板块 ≤ 25% (继承 PR-M4)
- 组合最大回撤 (60 日) < 20%
- PR-L 未触发 (若触发则冻新单, §5.4)

**L3 cost_gate**:
- ETF 折溢价绝对值 ≤ 0.5%
- 盘口买一/卖一距离 ≤ 0.3%
- 本次调仓换手率 ≤ 15% (单次), 年化 ≤ 200% (12 个月滚动)
- 冲击成本估算 (基于 20 日日均成交额 vs 本次订单量): 单笔冲击 ≤ 0.2%

**L4 ev_gate** (只对卫星, ETF 跳过):
- 公式: `EV = confidence × avg_win_pct - (1 - confidence) × avg_loss_pct`
- 阈值: EV > 0.5% 才下单 (锚定手续费 0.13% × 2 + 滑点 0.2-0.5%)

**举例** (卫星 BUY 信号):
- 胜率 40%, 平均赚 15%, 平均亏 8% → EV = 0.4 × 15% - 0.6 × 8% = **1.2%** → 下单
- 胜率 60%, 平均赚 3%, 平均亏 5% → EV = 0.6 × 3% - 0.4 × 5% = **-0.2%** → 拒绝 (虽然胜率高但赚小亏大)

**Gate 组合决策**:

```
if not L1_pass: skip (不合格, 记 gate_reason='eligibility_fail')
elif not L2_pass: skip (风控, 记 gate_reason='risk_fail')
elif not L3_pass: skip 或推迟 (成本, 记 gate_reason='cost_fail', 尝试次日)
elif signal_type == 'satellite' and not L4_pass: skip (EV 不足)
else: gate_pass = true
```

**参考来源**:
- Transaction Costs of Factor-Investing Strategies (ResearchGate 331912322)
- Rebalancing With Transaction Costs (SSRN 3495461)

### 5.3 自动化和用户拍板同源

**大白话**: 不管是人自己看信号决定买不买, 还是以后系统自动下单, **看的是同一份信号 + 同一份 EV gate 结果**, 不搞两套。区别只是"人 vs 机自动扣扳机"。

- 用户拍板: 所有信号 + gate_reason (通过/拒绝的原因) 展示给用户, 用户自己决定
- 自动化: gate_pass = true 才下单
- 两条路消费同一信号 + 同一 gate, 只在"是否触发下单"分岔

**用户 override (违反系统建议直接下单)**:
- UI 二次弹窗
- 手动写理由 (≥ 20 字, 入库)
- 记录 override 编号

**Override 冷冻规则**:
- 触发: 累计 override ≥ 10 次且亏损占比 > 60% (老不听系统还亏得多, 说明你在瞎搞)
- 分 regime (市场状态): 熊市阈值 = 80% (熊市谁都亏, 稍微宽松)
- 触发后冷冻 30 天, 期间只能跟系统信号

### 5.4 PR-L 与优先级

**大白话**: 如果整个组合大跌触发**紧急停损 (PR-L)**, 系统进入"防御模式"——不再开新仓, 但已有仓位的单笔止盈止损照常执行 (还是要保护已有的钱)。多种保护指令冲突时按下面顺序判断。

```
if PR-L 紧急停损触发:
  新信号: 全部 skip
  已持仓: 单笔止盈止损仍生效 (仓位保护优先)
  已触发 SELL 后: 转观察, 不再自动开新仓

优先级: PR-L 冻新单 > 单笔保护 > 时间止损
```

**PR-L 过渡期解除条件** (系统亏了太多进入紧急保护后, 什么时候恢复正常):
- Day 0-90: PR-L 保持 (实盘几乎冻结, 只跑纸面)
- Day 91-150: PR-L 部分解除 (允许小仓位, 5% 单仓)
- Day 151+: 完全解除条件 = "主线累计 ≥ 30 笔 且 win% ≥ 40%" (证明策略确实转好了)

## 8. 战略镜子

### 8.1 设计原则

**大白话**: 每月自己坐下来花 30-60 分钟, 用 6 道题看清"这个月赚亏的原因是什么, 下月怎么办"。每题必须写 4 层, 不能跳。**AI 只填客观数据, 主观归因和决定必须人写**——不然就变成"AI 说的算" 你就退化了。

每题 4 层固定 (不能跳):

```
层 1: 现状  → 数据是什么 (AI 填, 客观)
层 2: 评估  → 数据相对目标偏多远 (AI 算)
层 3: 归因  → 偏在哪里 (AI 建议, 用户手写至少一条)
层 4: 决定  → continue / 小调 / 切换 / 全停 (用户签字)
```

**分工**: AI 全填数据 + 建议, 用户 override。**必须至少一条归因手写**, 否则 §8.3 判定退化 (机制无效)。

**存放**:
- 模板: `docs/PROJECT_COMPASS.md`
- 月度归档: `docs/compass/YYYY-MM.md` (例如 `2026-07.md`)
- 数据 SQL: `scripts/compass/monthly_metrics.sql`

**节奏**: 每月第一个周末填一次。

### 8.2 6 题

| # | 主题 | 决定输出 |
|---|---|---|
| Q1 | 核心 (ETF 因子) 实盘表现 | continue / 调因子权重 / 切换 / 全停 |
| Q2 | 核心因子稳定性 | 因子不动 / 调权重 / 删加因子 |
| Q3 | 卫星 (题材) 表现 + 硬边界 | 卫星继续 / 冻结 / 永久停 |
| Q4 | 核心 vs 卫星 Sharpe 对比 | 比例不动 / 缩卫星 / 停卫星 |
| Q5 | 镜子机制自检 | 维持 / 调题目 / 暂停镜子 |
| Q6 | 下月承诺 (ToDo + 边界 + 数据焦点) | 具体到数字 |

### 8.3 硬阈值 (切换 / 卫星停 / 主线证伪)

**卫星停止** (触发任一条件都停):
- 60 天滚动窗口累计亏损 > 组合 5% → 冻结 30 天 (详见 §4.2 卫星硬边界)
- 自然月连续 3 个月月度 alpha < 0 → 永久停止 (中间任 1 个月 alpha ≥ 0 都重置)
- 单只 -15% (自持仓成本口径) → 强制平仓

**主线切换** (影响不到, 因为混合结构没有独立影子)

**主线证伪** (证明主线不行):
- 累计 ≥ 30 笔样本 (Wilson CI 有意义, 样本太少的结论不可信)
- 分 regime (牛熊震荡分开) 统计
- 连续 2 个月 win% < 30% 且 regime 相同 → 触发 §10 降级考虑

**镜子退化** (机制本身失效):
- 连续 2 个月手写归因 < 1 条 或 用户填写 < 5 分钟 → 暂停镜子机制 (你在应付了)

### 8.4 Q6 承诺硬约束

- ToDo 最多 5 项 (超过 5 项证明贪多, 一个都做不好)
- "不做"最多 3 项 (明确划边界)
- 数据焦点必须具体到数字 (例如"实盘 win% 从 0% 提升到 30%", 而不是"表现变好"这种模糊话)

## 9. 过渡期实施路径

**大白话**: 从今天到卫星上实盘, 大概 90 天。前 3 天冷静, 然后 3 波开发 (14 天基础 → 7 天 ETF 回测 → 14 天上核心), 期间实盘几乎冻结 (先跑纸面), 卫星 60 天后如果表现 OK 才上实盘。

### 9.1 时间线

| 阶段 | 天数 | 内容 |
|---|---|---|
| **冷却** | Day 0-3 | 重读全文, 校准 §11 待校准数字, 决定是否仍认同 §3 锁定 |
| **Wave 1** | Day 4-14 | 建 confidence / EV gate / ETF 框架 / 数据源 / PR-O5 修复 |
| **Wave 2** | Day 15-21 | ETF 因子回测 (2022-2026), 若年化 ≥ 10% 主线上线 |
| **Wave 3** | Day 22-35 | 删码, 核心 ETF 小仓位上线 (30 万 × 30% 试水, 就 9 万) |
| **观察** | Day 36-60 | 核心稳定, 卫星纸面积累 30-45 天数据 |
| **扩展** | Day 60+ | 卫星表现 OK 转实盘 (20% 上限) |
| **全量** | Day 90+ | 首次填战略镜子 |

### 9.2 关键分岔点

**Wave 1 → Wave 2** (基础建完能进入回测阶段吗):
- B-fusion 已停 (auto_trade off, 毒源已经不再运行)
- 实盘完全冻结
- 所有新 service 单测通过

**Wave 2 因子回测**: **上线验收标准**

**大白话**: 原来"2022-2026 回测年化达标即上线"判据偏快. 单一样本窗口 + 多重参数选择 (因子权重 / ETF 池 / 调仓规则 / 成本) 很容易选出**历史最好看但未来失效**的组合. 因此上线前必须通过下面**7 道验收关**, 全部达标才允许 Wave 3 小仓灰度.

**验收 7 关** (P0 硬约束):

| # | 关卡 | 定义 | 阈值 (V0 candidate) |
|---|---|---|---|
| 1 | **成本后年化** | 扣除双边手续费 0.13%×2 + 滑点 0.2-0.5% 后的年化收益 | ≥ 10% |
| 2 | **成本翻倍压力测试** | 手续费 × 2、滑点 × 2 (模拟实盘更差成本), alpha 仍要 > 0 | alpha > 0 |
| 3 | **Walk-forward** | 2022-2024 训练, 2025 测试; 2022-2025 训练, 2026 测试; 每年滚动一次 | 每期测试年化 ≥ 8% |
| 4 | **CSCV / PBO** | Combinatorially Symmetric Cross-Validation, 计算 Probability of Backtest Overfitting | PBO < 0.5 (Bailey et al.) |
| 5 | **参数扰动** | 因子权重网格 {(0.4/0.3/0.3), (0.35/0.35/0.3), (0.5/0.25/0.25)}, 三个 ETF 池 (V0 46 只 / 减 5% / 加 5%), Momentum shadow on/off | 各组合年化差异 ≤ 2%; 最差组仍 ≥ 8% |
| 6 | **最近 12 个月 OOS** | 2025-07 至 2026-06 (完全未训练), 单独跑一次 | 年化 ≥ 8%, 最大回撤 ≤ 25% |
| 7 | **Regime 分层表现** | 分牛 / 熊 / 震荡 (用沪深 300 60 日均线斜率界定), 每 regime 至少 6 个月样本 | 每 regime 年化 ≥ 5% (熊市可为负但 > -10%) |

**判定**:
- 7 关全过 → 主线上线, 目标 10-15% (原 12% 挡)
- 6 关过, 1 关介于阈值 ±10% → 部分采纳: 目标下调到 8-10%, 上线**灰度 30%** (仓位打 3 折)
- 5 关或以下过 → 主线不上线, 重新评估因子权重, 或触发 §10.4 全面降级

**参考来源**:
- Bailey et al., The Probability of Backtest Overfitting
- Invesco, Factor Investing in China: Beware Structural Breaks

**Wave 3 上线条件** (可以真上实盘吗):
- Wave 2 上线验收 7 关全过或 6 过
- 新 service 观察 3 天无 bug
- **首月强制小仓灰度**: 核心仓位 30 万 × 30% × 60% = 5.4 万 (原方案 9 万的 60%)
- 灰度期间每周做 live-vs-backtest drift report

**卫星上实盘 (Day 60+)**:
- 卫星纸面 30 天 win% ≥ 45% (纸面模拟能赢一半, 才有资格上真钱)
- 未触发 §4.2 硬边界
- Brier score < 0.20 (confidence 校准良好)

## 10. 失败降级路径

**大白话**: 主线依赖 3 个前置 (数据源 / 卫星探测器修复 / confidence 冷启动), 任一失败, 都有对应的**降级方案**——不硬撑, 直接砍功能保命。三个都失败, 只保留核心 ETF, 卫星彻底放弃。

主线依赖 3 个前置, 任一失败, 降级如下:

### 10.1 §6.1 数据源失败

**触发**: 8 天内爬虫合规 / IP 池被封 / LLM 成本超预算 200% (200 块还打不住)

**降级**:
- 砍备用渠道, 只用主渠道 (新浪 RSS + 证监会 API)
- LLM 分类关闭, 只用规则关键词字典 (硬编码"AI关键词"当分类)
- 卫星 alpha 减半, 硬边界从 5% 缩到 3% (数据质量降了, 更严格控风险)

### 10.2 §6.2 PR-O5 修复失败

**触发**: 上游 `LIMIT_UP_SYNC` 超 3 天调试无果 (数据抓不进来)

**降级**:
- 卫星推迟到 Q4 (等数据源恢复)
- 卫星资金转入核心 (核心 90% + 现金 10%)
- 目标降到 8-12% (纯 ETF 因子上限, 没了卫星就少了博高收益的部分)

### 10.3 §5.1 confidence 冷启动失败

**触发**: default 30% 造成卫星实盘连续 5 笔亏损 (2 周内) —— 说明用 30% 作先验太乐观

**降级**:
- 卫星冻结 30 天, 只跑纸面
- confidence default 从 30% 下调到 20% (更悲观, 更多信号被 EV gate 挡掉)
- 30 天后基于纸面数据重新评估

### 10.4 全部前置失败的终极降级

**触发**: 三个前置在 60 天内都跑不通

**处置**:
- 核心继续 (ETF 因子学术支持稳, 至少这块能吃)
- 卫星彻底放弃
- 组合结构变为 核心 80% + 现金 20%
- 目标降到 8-12%
- 战略镜子开特殊 review, 讨论项目是否继续 (值不值得继续投入时间)

## 12. 元教训 (工作方法层)

**大白话**: 这些是**做这个项目的过程本身**教会的经验, 不是股票策略, 但影响后续所有决策。

这些是这次会话本身的产出, 不是项目内容, 但影响后续所有工作:

### 12.1 讨论方法

- 单次会话极限 = 走出方向, 不是产出可执行方案 (一次讨论最多定"往哪走", 别指望一次讨论完就能开工)
- 每次锁定大决策前, 用 sub-agent 模拟"苛刻外部审计员"挑刺 (让 AI 反串审计员来找漏洞)
- 审计员发现的漏洞会推翻锁定 (今天发生过一次: 题材 → ETF 混合)
- AI 会默认接住用户方向 (确认偏差), 除非被明确要求挑战 —— 你说啥 AI 都说"你说得对", 得主动要求它反驳

### 12.2 数字使用

- "持仓部分年化" vs "组合年化" 是单位差异, 混用会造成 60-70% 期望落差
    (卫星本身年化 50% 听着牛, 但只占 20% 仓位, 对组合贡献只有 10%)
- "梦想数字" (例如 50% 年化) 若不校准, 会绑架整个方案设计
- 沉没成本偏差最明显的迹象: "看机会加仓" / "先留着以防万一" —— 出现这种话就是在为已经亏的东西找借口

## 13. 运维保障 (回滚 / 监控 / 数据回填)

**大白话**: 每次改代码都可能出问题。这一章讲**出问题咋办**——怎么快速回滚、怎么监控预警、怎么补历史数据。

### 13.1 回滚方案

**核心原则**: 每次删码 / 改写 / 新建都必须**可回滚**, 且回滚时间 < 15 分钟。

**分级回滚**:

| 级别 | 触发场景 | 回滚方式 | 耗时 |
|---|---|---|---|
| L1 单 PR 回滚 | 某个新 service 上线后 bug | `git revert <commit>` + 重新部署 | 5-10 分钟 |
| L2 主线整体回滚 | 核心 ETF 主线首月负 alpha 严重 | 切回 auto_trade off + PR-L 冻结 | 10 分钟 (无需回滚代码, 只关开关) |
| L3 版本回滚 | 大范围失败, 需要回到之前版本 | 从 `releases/` 目录切 symlink | 15 分钟 |
| L4 数据回滚 | DB schema 变更后失败 | 从每日备份恢复 (pg_dump 已存在) | 30-60 分钟 |

**关键约束**:
- **B-fusion 代码删除前必须先跑 30 天新自动化层影子对比**, 确认新逻辑不比 B-fusion 差之后再删 (不能一下子拆房子)
- **删码前必须打 tag**: `git tag pre-delete-b-fusion-2026-07-XX`, 便于紧急恢复
- **DB 变更必须两阶段**: 先加字段 (向后兼容), 观察 7 天, 再删字段
- **禁止**: 单个 PR 里同时删多个模块的代码 (哪个坏了不知道)

**回滚决策权**:
- L1/L2: 用户单独决定
- L3: 用户 + 战略镜子 Q5 讨论
- L4: 必须留证据 (log + 数据快照), 战略镜子专项 review

### 13.2 监控告警

**监控分 3 层** (从底层到业务):

**系统层** (基础设施):
- Cron 任务 stuck / 失败 → 飞书 OPS 告警
- DB 连接失败 / 慢查询 → 飞书 OPS
- 磁盘 / 内存超阈值 → 飞书 OPS
- (保留 PR-A / 已有基础设施)

**业务层** (信号 / 交易):
- 主线月度再平衡未触发 (次月第一交易日 10:00 仍无信号) → 用户飞书通知
- 卫星连续 3 笔亏损 → 用户飞书通知 (提前警示硬边界)
- Confidence 计算失败 (依赖数据缺) → 用户飞书 + 战略镜子 Q1 数据标"未知"
- Override 触发 → 用户飞书通知 + 入库审计
- PR-L 触发 → 用户飞书**紧急**通知 (置顶)

**指标层** (性能 / 趋势):
- 每周日晚生成一份指标简报 → 飞书自己
  - 本周组合收益率
  - 核心 vs 卫星 PnL 分解 (盈亏分别多少)
  - 卫星硬边界距离 (剩余 X% 触发)
  - Override 次数 / 亏损占比
- 战略镜子月度自动 draft → 飞书自己

**告警渠道**:
- 用户飞书 OPS 群 (已有基础设施, PR-C 通知中心)
- 不发短信 / 电话 (成本 + 打扰)
- **不发用户手机 push** (手机推送 = 强弹屏, 用户是初炒者会加剧情绪化操作). 飞书消息**允许** (飞书是"打开才看", 不是强弹).

**静默期**:
- 用户在飞书标 "静默"后 24 小时内不发非紧急通知
- 但 PR-L 触发 / 卫星硬边界触发**永远发**

### 13.3 信号日常触达 (盘前 + 实时 + 收盘 三层)

**大白话**: 卫星 BUY 信号什么时候提醒你? 用**三层递进**——盘前一个摘要预告今天可能有啥, 盘中实时推关键信号 (但每天最多 5 条防轰炸), 收盘一个日总结. 全部走飞书, **不推手机 push**.

**层 1 — 盘前摘要 (每交易日 8:30)**

- 内容:
  - 今日预计的核心 ETF 再平衡信号 (若是月度触发日)
  - 昨日新产生但未处理的卫星 BUY 信号 (供 T+1 决策)
  - 卫星硬边界距离 (例: 60 天累计亏损 -2.1%, 距 5% 边界还有 2.9%)
  - PR-L 状态 (正常 / 触发中 / 部分解除)
- 空日也发 (只有一行"今日无新信号, 组合无异常"), 让你确认系统在跑
- 送达: 飞书 OPS 群

**层 2 — 盘中实时 (盘中 9:30-15:00, 严格限流)**

**默认关闭**, 只在明确开启后才推 (设置里开关). 开启后规则:
- **每交易日最多 5 条** (超过 5 条改为聚合成"过去 30 分钟内又有 3 条", 每 30 分钟一次)
- **只有以下类型才推**:
  - 卫星 BUY 信号已通过 EV gate (`gate_pass = true`)
  - 单笔止损触发 (深止损 -15% 或组合 PR-L)
  - 卫星硬边界警戒 (距离 <1% 时)
- **不推**:
  - 卫星信号被 EV gate 拒绝 (`gate_pass = false`) — 盘后再看
  - 核心 ETF 因子日常波动
  - Confidence 计算完成
- 每条消息带 UI 直链, 用户点开二次确认

**层 3 — 收盘日总结 (每交易日 15:30)**

- 今日新产生的所有信号 (通过 gate + 被拒绝的都列出)
- 今日已执行的交易 (若开自动化)
- 今日组合 PnL (核心 / 卫星分开显示)
- 明日预告 (若明天是月度再平衡日, 提前 1 天预热)

**告警优先级** (多条并存时的顺序):
1. PR-L 触发 (置顶, 永远发)
2. 卫星硬边界触发 (永远发)
3. 层 2 实时信号 (受限流)
4. 层 1 盘前 / 层 3 收盘 (定时)
5. 系统层告警 (cron / DB)

**触达渠道对照表**:

| 事件 | 层 1 盘前 | 层 2 实时 | 层 3 收盘 | 手机 push |
|---|---|---|---|---|
| 卫星 BUY 通过 EV | ○ (聚合) | ● (若开开关) | ● | ✗ |
| 卫星 BUY 被 EV 拒 | ✗ | ✗ | ● | ✗ |
| 单笔 -15% 止损 | ✗ | ● | ● | ✗ |
| 卫星硬边界警戒 | ● | ● (距 <1%) | ● | ✗ |
| 卫星硬边界触发 | 立即 | 立即 | 立即 | ✗ (飞书够) |
| PR-L 触发 | 立即 | 立即 | 立即 | ✗ (飞书置顶) |
| 核心 ETF 再平衡 | ● (触发前 1 天) | ● (触发时) | ● | ✗ |
| Override | ✗ | ● (立即, 审计) | ● | ✗ |
| Confidence 计算失败 | ○ (聚合) | ✗ | ● | ✗ |

**图例**: ● = 必推; ○ = 有内容才推; ✗ = 不推

### 13.4 数据回填

**大白话**: 系统要跑 ETF 因子和 confidence, 需要**历史数据**——过去几年每天每只 ETF 的价格 / 财务指标 / 每条历史信号的结果。这些以前没存, 现在得补上, 大概 3-4 天工作量, 严格按依赖顺序补, 补完做质量检查。

**背景**: Wave 1 建 ETF 因子需要历史因子数据, 建 confidence 服务需要历史 win% 数据, 两者都要 backfill (补历史)。

**回填任务清单**:

| 任务 | 数据 | 时间窗 | 工作量 | 前置 |
|---|---|---|---|---|
| **T1** | daily_bars for 50 只候选 ETF | 2022-01-01 至今 | 0.5 天 (已有 PR-N / 增量 sync) | 无 |
| **T2** | ETF 成分股财务因子 (PB/PE/ROE/股息率) | 每月 1 次快照, 2022 至今 | 1 天 | T1 |
| **T3** | 因子分历史 (Value/Quality/LowVol/Momentum for each ETF) | 从 T1+T2 计算, 每月 1 次快照 | 0.5 天 | T1, T2 |
| **T4** | `limit_up_stocks` 历史 (卫星 detector 依赖) | 2026-06-02 至今 (§6.2 提到) | 0.5 天 | 无 |
| **T5** | `theme_fermentation_phases` 历史 | 用 T4 + `industry_sentiment_indices` 计算 | 0.5 天 | T4 |
| **T6** | 历史信号 (`ai_investment_signals`) 迁移 | 保留 tradingagents 部分, 打 archive tag | 0.5 天 | 无 |
| **T7** | `recommendation_trade_outcomes` 历史 | 保留全部 (战略镜子 Q1 用) | 0 天 (已有) | 无 |

**总耗时**: 3-4 天 (与新代码开发并行)

**回填错误处理**:
- 数据源 API 失败 → 记录到 `data_update_logs` 表, 手动重试
- 部分数据缺失 (如某 ETF 2022 年数据不全) → 该 ETF 从候选池删除
- Backfill 期间 prod 服务**必须停** (auto_trade off), 避免半态数据触发错误信号
- 每步 backfill 完成后写一份**快照报告** (`docs/backfill/YYYY-MM-DD-taskX.md`) 记录: 数据量、缺失情况、决定

**Backfill 顺序** (严格依赖):
1. T1 (基础数据)
2. T4 (卫星基础数据, 与 T1 并行可)
3. T2 (依赖 T1)
4. T3 (依赖 T1 + T2)
5. T5 (依赖 T4)
6. T6/T7 (保留处理)

**回填质量门**:
- T1-T5 完成后, 跑一次**完整性检查**: 每个 ETF 至少有 90% 交易日数据, 因子分不为 null
- 完整性 < 90% 的 ETF 从候选池删除
- 完整性 90-99% 的 ETF 保留但标注"数据有缺失"
