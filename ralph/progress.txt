# Ralph Progress Log — QuantX A-Share Alpha Refactor

## Codebase Patterns

### Frontend
- **Frontend workspace shells live under** `frontend/src/pages/workspace/`. Each is lazy-loaded in `frontend/src/App.tsx`. When adding workspace tabs in later stories, edit the shell file in place — do NOT introduce parallel page files.
- **All 6 workspace shells use `WorkspaceLayout`** (`frontend/src/components/layout/WorkspaceLayout.tsx`). When a future story adds real content for a workspace, render the new tab UI as `children` (or branch on `activeKey`) and leave the KPI strip / side rail handled by the layout — do NOT rebuild the chrome from scratch.
- **WorkspaceLayout props contract:** `tabs[]` (each `{key,label,icon?}`) → 220px left rail; `kpiSlot` → centered metrics inside the 96px KPI bar; `headerActions` → right-aligned `Space`; `activeKey` / `onTabChange` are required to drive the side-rail selection.
- **App.tsx single source of truth** for routes and the top-level menu. The `routeSelectionAliases` array maps legacy paths to the workspace whose sidebar entry should be highlighted; the `<Routes>` block defines the actual `<Navigate>` redirects. Whenever a legacy path is deprecated, update BOTH arrays.
- **Legacy page imports** are kept (under `/legacy/*` routes) so deep links and embedded iframes still resolve. Only physically delete a page file after all six workspaces have absorbed its functionality (stories US-015..US-018).
- **Workspace shell CSS lives at the bottom of `frontend/src/index.css`** under a `Workspace shell (US-002)` banner. The shell uses `.workspace-shell`, `.workspace-kpi-bar__inner`, `.workspace-side-tabs`. Media query at 1024px stacks the side rail above content.

### Backend
- **PaperTrading services live under `backend/src/portfolio/internal/`**, not `backend/src/services/` (US-003 refactor). The public surface is `backend/src/portfolio/PaperTradingFacade.ts` exposing **exactly 7 methods**: `getPortfolio`, `placeOrder`, `closePosition`, `getDailySnapshot`, `attributePnl`, `applyAutomation`, `getRiskProfile`. Controllers MUST only import the facade. Other services/scripts/jobs may still import from `internal/` directly (the facade-only constraint is the controller boundary).
- **When adding a new paper-trading action**, extend the discriminator union (e.g. `ApplyAutomationAction`) inside `PaperTradingFacade.ts` — do NOT add an 8th method. The `switch` blocks use a `never`-typed default branch to catch missing cases at compile time.
- **Constants re-exported by facade:** `DEFAULT_PAPER_TRADING_INITIAL_CAPITAL`, `AUTONOMOUS_PORTFOLIO_NAME`, `DEFAULT_AUTONOMOUS_INITIAL_CAPITAL`, `QUANT_ONLY_PORTFOLIO_NAME`. These were previously exported from `PaperTradingAutomationService` and `PaperTradingDashboardService`; controllers/tests now pull them from `../../portfolio/PaperTradingFacade`.
- **Quant services live under `backend/src/quant/{engine,backtest,performance,health}/internal/`** (US-004 refactor). The public surface is **exactly 5 classes**: `StrategyEngine` + `SignalEngine` (engine/), `BacktestEngine` (backtest/), `PerformanceReporter` (performance/), `QuantHealthMonitor` (health/). Controllers MUST only import these 5 facades; non-controller code (Scheduler, Jobs, sibling Services) may still reach into `internal/`. The facade design and method index live in `backend/src/quant/CLAUDE.md` — update that, not this file, when adding new facade methods.
- **Cross-layer sibling imports inside quant** use explicit `../../<layer>/internal/...` paths (e.g. `engine/internal/QuantFusionService` imports `quantRuntimeHealthService` from `../../health/internal/QuantRuntimeHealthService`). Don't add wildcards or re-export barrels — staying explicit makes the inter-layer graph visible to future readers.
- **`QuantMath.ts` and `StrategyRegistry.ts` stay at `quant/engine/` top level** (NOT in `engine/internal/`). They're imported by every strategy under `strategies/`; moving them would force strategies to reach into `internal/`. Treat them as shared primitives, not part of the facade-internal split.
- **Symlinks for tooling in the worktree** — the worktree has no `backend/node_modules`. Before running typecheck, symlink: `cd backend && ln -s /Users/bytedance/go/src/github.com/bruinxz/stocks/backend/node_modules node_modules`. The repo's `backend/.gitignore` matches `node_modules/` as a directory pattern but the symlink shows up as an untracked symlink — REMOVE it before `git add` to keep the tree clean.

### Tooling

- **Discriminated-union actions beat method-count explosions.** The AC mandated 7 methods but the controller had ~25 endpoints. Folding endpoint families into `action`/`view` enums on a small fixed method surface scales without violating the contract. Use `default: const _: never = action` to keep the switch exhaustive.
- **Don't try to keep service singletons stable across the move.** The exported `paperTradingAutomationService = new PaperTradingAutomationService()` lives at the bottom of each internal file unchanged — the facade just imports the existing singletons. No DI rewiring needed.
- **Sequelize models did NOT move.** All `PaperTrading*` models (Portfolio, Position, Trade, Snapshot, OrderIntent, etc.) still live in `backend/src/models/`. Only the *services* moved. The facade imports models directly because the `placeOrder`/`getPortfolio` path was previously inlined in the controller.
- **Backend has no Jest tests yet for these services** — the typecheck IS the test gate. When US-004+ adds tests, they should target the facade (the new public surface), not internal services, to avoid coupling tests to the now-private layer.
- **`recommendationTradeOutcomeService` is at the boundary** — it lives in `src/services/` and is imported by both the facade and several internal PaperTrading services. It was deliberately NOT moved into `portfolio/internal/` because it's also consumed by non-paper-trading flows (`RecommendationTradeOutcomeService` itself is a candidate for the US-004 quant consolidation).
- **Backend Lint has pre-existing churn.** Running `eslint --fix` repo-wide would touch ~500 unrelated files. Only `--fix` files you actually changed; let the rest stay until a dedicated formatting pass.
- **`backend/src/portfolio/CLAUDE.md` is now the documentation source** for the facade contract — update it (not progress.txt) when adding new actions to the discriminator unions.

### Learnings for future iterations
- **The 5-facade ceiling is non-negotiable per the AC** (StrategyEngine, SignalEngine, BacktestEngine, PerformanceReporter, QuantHealthMonitor). When a new behaviour doesn't obviously fit into one of those buckets, add a method to the closest match rather than spawning a 6th facade. The original draft tempting was a separate "ParamVersionEngine" — folded into StrategyEngine instead, matching how the controller already grouped those endpoints.
- **Returning `any` from facade methods short-circuits TS4053**. `QuantFusionService.runDailyPipeline()` has a complex internal return type referencing the un-exported `QuantFusionCandidate`. Re-typing the facade method as `Promise<any>` avoided cascading every internal type out to the public boundary (which would have leaked implementation details). Keep this trick scoped — only `runDailyPipeline` needed it.
- **Keep `QuantMath.ts` and `StrategyRegistry.ts` at `engine/` top level**, NOT in `internal/`. The 17 strategy files under `quant/strategies/` import from there directly. Pushing those primitives into `internal/` would force the (non-internal!) strategies to reach into `internal/`, which contradicts the layering intent and creates a 17-file churn for no benefit. Treat them as a third tier of pure helpers.
- **`git mv` for services + a single bulk `sed` for `../../` → `../../../` import paths** is the fast path. Then handcraft the cross-layer references (sibling imports `./QuantXxx` that crossed layers had to become `../../<layer>/internal/QuantXxx`). I also had to relocate `QuantBacktestEngine` from `engine/` into `backtest/internal/` so its sole consumer (QuantBacktestService) could keep a same-directory import — keeping co-located callers together makes the layer assignment self-documenting.
