# Ralph Progress Log — QuantX A-Share Alpha Refactor

## Codebase Patterns

- **Frontend workspace shells live under** `frontend/src/pages/workspace/`. Each is lazy-loaded in `frontend/src/App.tsx`. When adding workspace tabs in later stories, edit the shell file in place — do NOT introduce parallel page files.
- **All 6 workspace shells use `WorkspaceLayout`** (`frontend/src/components/layout/WorkspaceLayout.tsx`). When a future story adds real content for a workspace, render the new tab UI as `children` (or branch on `activeKey`) and leave the KPI strip / side rail handled by the layout — do NOT rebuild the chrome from scratch.
- **WorkspaceLayout props contract:** `tabs[]` (each `{key,label,icon?}`) → 220px left rail; `kpiSlot` → centered metrics inside the 96px KPI bar; `headerActions` → right-aligned `Space`; `activeKey` / `onTabChange` are required to drive the side-rail selection.
- **App.tsx single source of truth** for routes and the top-level menu. The `routeSelectionAliases` array maps legacy paths to the workspace whose sidebar entry should be highlighted; the `<Routes>` block defines the actual `<Navigate>` redirects. Whenever a legacy path is deprecated, update BOTH arrays.
- **Legacy page imports** are kept (under `/legacy/*` routes) so deep links and embedded iframes still resolve. Only physically delete a page file after all six workspaces have absorbed its functionality (stories US-015..US-018).
- **Frontend node_modules are in the main repo, not the worktree.** Run `ln -s /Users/bytedance/go/src/github.com/bruinxz/stocks/frontend/node_modules frontend/node_modules` inside the worktree before `./node_modules/.bin/tsc --noEmit` or eslint. REMOVE the symlink before `git add` — gitignore matches the directory pattern but not the symlink file.
- **Lint command:** `cd frontend && ./node_modules/.bin/eslint src --ext .ts,.tsx --quiet` (errors only). Warnings are prettier nags — use `--fix` to auto-resolve.
- **Typecheck command:** `cd frontend && ./node_modules/.bin/tsc --noEmit` (exits 0 = clean).
- **Browser verification:** No `dev-browser` MCP skill is configured in this environment. UI stories should fall back to manual verification and note that in progress.txt.
- **Workspace shell CSS lives at the bottom of `frontend/src/index.css`** under a `Workspace shell (US-002)` banner. The shell uses `.workspace-shell`, `.workspace-kpi-bar__inner`, `.workspace-side-tabs`. Media query at 1024px stacks the side rail above content.

### Learnings for future iterations
- **The PRD's "6 workspaces" must literally be 6 flat menu items, not submenu groups.** The original App.tsx used nested submenus with 20+ leaf items; collapsing them into flat top-level entries is what unblocks downstream stories (US-002 onwards) that assume one-tab-per-workspace.
- **Legacy menu used Chinese labels** ('今日作战' '量化交易' '复盘' '实盘' '数据与系统' '账号与设置'). Keep Chinese labels for consistency — A-share users prefer them.
- **`routeSelectionAliases` must be updated whenever you add or remove routes** or the sidebar will highlight the wrong workspace when users land on a legacy URL. The aliases use anchored regex (`^...$`) so each legacy path family needs its own entry.
- **Antd Menu with flat (no children) items still highlights correctly** via `selectedKeys`. No need for `<Menu.SubMenu>` wrappers.
- **`useParams` and `BacktestDetailRoute` were preserved** — `/backtest/:id` is still reachable under `/legacy/backtest/:id` for any saved bookmarks.
- **Worktree gotcha:** the worktree has no `frontend/node_modules`. Symlinking to the main repo's copy works for typecheck/lint but the symlink shows up as a tracked-able file in `git status` (NOT matched by `node_modules/` gitignore pattern). Always `rm frontend/node_modules` before `git add`.
- **The original App.tsx had a profile-fetch effect** keyed on `[token, user, dispatch]` — preserved unchanged. Auth flow still works because Login route is unchanged and the dropdown still calls handleLogout.

### Learnings for future iterations
- **Use `WorkspaceLayout` for any new workspace content.** When implementing US-015..US-018, render real content as `children` and switch on the existing `activeKey` rather than reintroducing your own Card/Menu chrome. The KPI slot already centers in the bar; the side rail already handles selection styling.
- **`bodyStyle` is the supported escape hatch on antd Cards in this project** (Dashboard.tsx uses it heavily). antd v5 deprecated it in favor of `styles={{ body }}`, but ESLint/TS in this repo are still happy with the old form — staying consistent avoids a multi-file migration mid-story.
- **Each shell exposes secondary tabs that mirror the eventual full pages.** Don't rename these keys casually — when US-015 adds the real "因子总览/权重调参/今日选股清单" content, it can deep-link via `?tab=overview` etc. without breaking the contract.
- **Empty-state cards must use antd `Empty`**, not raw text, so the global Card border-radius (`16`) and the Empty illustration stay visually consistent across all 6 workspaces.
- **Don't add anything to `frontend/src/components/layout/` other than the shell** until at least one other layout primitive earns its keep — the directory is intentionally small so future shells (e.g. a dual-pane workspace) are easy to find.
- **Window-resize tip**: at <1024px the media query stacks the side rail above content. If a future story needs a horizontally scrollable tab bar at narrow widths, switch the side `Menu` to `mode="horizontal"` inside the same media query instead of bypassing the layout.
- **Imports were kept minimal in each shell** (only the icons each one actually uses). Resist the temptation to centralize a "all workspace icons" barrel — it makes tree-shaking worse and obscures which workspace owns which icon.
