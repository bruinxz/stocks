- **Learnings for future iterations:**
  - **"caller-side 5 行重复 → 抽成 handleRiskGuardUnavailable" 是项目"统一 helper"的标准时机**: BETA-7 落 DrawdownCircuitBreaker 时 inline 在 facade + preTradeGuards 写了 30 行 catch+RiskAlert.create+rethrow 块. 一旦第三处也复用 (PositionLimitGuard fail-CLOSED), 必须抽 helper — 否则 (a) message/metadata 漂移 (facade 一处先加 ⚠️ 另一处忘加); (b) 新 guard 接入时漏掉 try/catch 静默 fail-OPEN. 本次三件套 wrapFailClosed (guard-side) + handleRiskGuardUnavailable (caller-side) + GUARD_LABELS (人类标签表) 是"重复 3 次必须 DRY"原则的实例.
  - **wrapFailClosed 把 programmer-error 也守住 503 是 fail-CLOSED 的关键放大**: 如果 wrap 只 re-throw RiskGuardUnavailableError + 让其它 Error propagate, 那么任何 TypeError ('Cannot read property of undefined' 之类 guard 自身 bug) 会跳过 caller 的 catch 块 (caller 只 catch RiskGuardUnavailableError instanceof) 直接 500 给用户. wrap 把 unexpected Error 也转 503 等于"guard 自身 bug 也走 fail-CLOSED" — 用户体验始终是"风控不可用"安全语义而非裸 stacktrace 泄露 + 技术上的 fail-OPEN.
  - **back-compat re-export 是项目"单一事实源"模式的标配收尾**: DrawdownCircuitBreaker.ts 原 export class RiskGuardUnavailableError 被 5+ 外部文件 (preTradeGuards / PaperTradingFacade / 多 .test.ts) import. 直接删 class 会全断. 改成 `export { RiskGuardUnavailableError } from './RiskGuardFailClosed'` 让 existing import 路径不变, 但 single source of truth 在新文件. 任何"抽 helper 时遇到现有公开 API"都该用这套.
  - **meta-test 验"不再做 X" 用 ! 否定 regex**: 比起验"必须有 X", 验"不能 inline 写 RiskAlert.create({...SYSTEM:RISK_GUARD_UNAVAILABLE...})" 是项目第一次出现 — 因为本次重构的核心契约是"caller 不能再 inline duplicate, 必须走 helper". 否定 meta-guard 比正向更易守: 未来谁要把 30 行 inline 写回 facade.ts, 这个 test 立刻挂. 通用模式: `!/pattern/.test(src)`.
  - **wrap-helper 后 caller 的 try/catch 仍要保留**: 即便 guard 内 wrapFailClosed 已经 converge 所有 throw 都是 RiskGuardUnavailableError, caller 的 try/catch + `instanceof` 检查仍要保留 — 因为 caller 必须把 RiskGuardUnavailableError 转成业务态 (facade 把它 propagate throw / preTradeGuards 把它 map 成 {ok:false, code:'RISK_GUARD_UNAVAILABLE'} 返回). caller 的 catch 不只 log, 还要 emit RiskAlert + 决定下游协议. 不要因"看上去 guard 都包好了"就删 caller 的 try/catch.
