## Codebase Patterns
- Backend tests 不依赖 jest：每个 `tests/**/*.test.ts` 自带 assert 框架并 `process.exit`，由 `src/scripts/run-tests.ts` 串行 spawn 子进程跑 (`npm test`)。
- EnvValidator (`backend/src/config/EnvValidator.ts`) 是项目环境一致性校验的唯一事实源：`validateEnv()` 返回 `EnvValidationResult`，`shouldExitOnFailure()` 决定是否 exit。任何新增 required env 都加到 `buildBaseSchema()`，同步更新 `.env.example` 与 docs/deploy。
- `backend/src/index.ts` 第 1 行 dotenv.config，第 18 行 validateEnv，再 productionPreflight。任何强制启动检查都加这里。
- CI workflow (`.github/workflows/ci.yml`) `backend-check` job 顺序：install → env-check(happy) → env-check(fail) → typecheck → lint → test，失败上传日志并在 PR 评论。
- 多通道 dispatcher (任何"fan-out 到飞书/邮件/短信/inbox"的 service) 复用同款模板: (1) DataSource interface + Production 实现 lazy-require model/service 单例; (2) 纯函数 helpers (normalizeXxx / buildChannelPlan / buildOpsAlertText / buildXxxSubject) 全 export 便于单测; (3) Promise.allSettled 并行 fan-out + 每个 channel adapter 内部 try-catch 返 {success,message} 而非 throw; (4) 顶层 try/catch 兜底 + logger.warn 吞错 — 主流程绝不被告警链路阻塞; (5) options.dry_run=true 强制空 plan 让 UI 预览不实际发. 参考 RealtimeAlertDispatcher / RiskAlertService / audit-task-parameters-dry-run.
